## AI 辅助的算法学习

这个仓库同时在试一件事：**用 AI 把"学算法"这件事记录清楚**。

传统练习仓只留下题解和代码，看不出练习的真实过程——哪道题卡了多久、是不是看了题解才过、
练了一段时间到底有没有变强，全都凭感觉。这里换了个做法：

| 环节 | 谁做 | 做什么 |
| :-- | :-- | :-- |
| **做题** | 我 | 只写一行流水：`日期 / 平台 / 题号 / 结果 / 是否独立 / 用时` |
| **整理** | AI | 把流水补成结构化记录，归档、校验、汇总 |
| **记录** | AI | 生成可核对的练习记录，替代"凭感觉"的自我评估 |

设计上有三条硬规则：

1. **"是否独立做出来"是必记项**。AC 数可以刷（抄一遍也算 AC），只有独立完成度能把
   "真的会了"和"看着像会了"区分开；没标这一项的题，不计入独立完成率。
2. **数据不够就不下结论**。比赛场数少时只列事实，不说"进步 / 退步 / 趋势"——
   用两场比赛谈进步，和凭感觉没有区别。
3. **讲义与题解不算成绩**。AI 生成的讲义、题解只说明"读过、梳理过"，不代表会做。

这套东西长这样：

```
随手记/        ← 我写的流水（一行一题）+ 随手丢的材料
   ↓  AI 整理
.ai/           ← 结构化记录（比赛 / 训练）+ 汇总脚本
   ↓
记录.html      ← 汇总出来的网页
```

> 这是仓库在**学习方法**上的一点尝试，属于仓库内容的一部分。

### 学习模块的三层

| 层 | 用途 |
| :-- | :-- |
| `01-参考层/` | 遇到问题时快速查阅：STL、`algorithm`、IO、常用函数 |
| `02-学习层/` | 按块读的讲义，不要求通读 |
| `03-实战层/` | 做题时复制粘贴：算法模板、踩坑记录 |

`02-学习层/01-C++/` 下分四块：

```
01-C++基础语法/   ← 语法底座
02-数据结构/      ← STL 工具箱（备赛） / 教材轨（深造）
03-基础算法体系/  ← 暴力、排序、二分、贪心、搜索、前缀和、双指针…
04-进阶算法体系/  ← DP、图论、数论（ACM 开轨后）
```

## 语言与约定

全部用 **C++**。

两条硬规则：

- **禁止万能头文件**——不使用 `#include <bits/stdc++.h>`，按实际用到的显式列出标准头文件
- **题解必须验证**——`g++` 编译通过，且与暴力解在小数据上对拍一致，才归档

## 题解规范

| 文件 | 说明 |
| :-- | :-- |
| `题解.md` | 题目描述 + 思路拆解 + 易错点 + 算法总结 |
| `solution.cpp` | 主解法 |
| `<解法名>.cpp` | 多解法，按解法特征命名，如 `暴力枚举.cpp`、`贪心法.cpp` |

落点：洛谷题 → [`题解归档/洛谷/`](题解归档/洛谷/)；蓝桥真题 → [`题解归档/蓝桥杯/真题强化24/`](题解归档/蓝桥杯/真题强化24/README.md)

## Commit 规范

| 前缀 | 说明 |
| :-- | :-- |
| `feat:` | 新增题目解法 |
| `fix:` | 修复代码或补充边界处理 |
| `docs:` | 更新题解、讲义、竞赛轨 |
| `refactor:` | 重构代码实现 |
