# 代码书写核心规则（必须遵守）

- **头文件规范**：所有C++代码必须显式列出标准头文件，**严禁使用 `#include <bits/stdc++.h>`**。
- **输入陷阱处理**：若题目涉及含空格输入或混合输入（如先读数字再读含空格的字符串），必须在"逐步讲解"的代码中实际使用 `cin.ignore()` 并注释说明，若题目为纯数字输入则无需使用。
- **数据类型选择**：浮点数一律使用 `double`，大整数使用 `long long`，并在注释中解释理由。
- **布尔标记数组规范**：所有需要标记 true/false 状态的大数组（如筛法、访问标记），强制优先使用 `vector<char>` 而非 `vector<bool>`。原因：`vector<bool>` 是 C++ 标准库的特化模板，其 `operator[]` 返回的是代理对象而非真正的 `bool&`，会导致无法取地址、某些编译器优化异常等问题，初学者极易踩坑。使用 `vector<char>` 内存仅多占 7 倍（100 万个 char 约 1MB），完全可接受，且行为与普通数组一致，更加安全直观。

# C++专项深度要求（面向初学者的C++教学强化）

## 1. 头文件教学深度

在"逐步讲解"中，**逐个解释每个头文件提供了什么功能**：

- `<iostream>`：提供 `cin`、`cout` 等输入输出流对象
- `<cmath>`：提供 `sqrt()`、`pow()` 等数学函数
- `<string>`：提供 `string` 类型和相关操作
- `<iomanip>`：提供 `setprecision()`、`fixed` 等格式化输出工具
- `<vector>`、`<algorithm>` 等STL头文件也需说明用途

**通俗来说**：就像工具箱，每个头文件装着不同的工具。

## 2. C++特有语法讲解

若代码中出现以下C++特性，**必须在注释或解释中说明**：

- `using namespace std;`：为什么用？有什么风险？（命名空间污染）
- `vector` 与普通数组的区别及何时选用
- `&` 引用传递：为什么用引用？值传递有什么问题？
- `const` 修饰符：什么时候用？有什么好处？
- 范围for循环 `for (int x : arr)`：与传统for循环的区别

**目标**：让初学者不仅知道"怎么写"，更理解"为什么这样写"。

## 3. C++调试技巧教学

在"易错点"或"逐步讲解"中，适当提示：

- 用 `cout` 输出中间变量验证逻辑（如"质数判断时，输出每个数的判断结果"）
- 用 `cerr` 输出错误信息，避免干扰正常输出
- 小数据测试法：先用小规模数据验证代码正确性

## 4. C++内存管理意识

- 若使用静态数组，说明其内存在**栈**上分配，大小需编译期确定
- 若使用 `vector`，说明其内存在**堆**上分配，可动态扩容
- 简单解释栈与堆的区别（栈快但小，堆慢但大），并说明本题为何选择某种方式

## 5. C++代码风格规范（强制）

- **变量命名**：优先采用算法竞赛中的通用简写（详见下方“算法常用命名速查表”），例如：
  - 计数器用 `cnt`，不用 `counter`
  - 访问标记用 `vis`，不用 `visited`
  - 动态规划数组用 `dp`，不用 `dynamicProgramming`
  - 答案用 `ans`，不用 `answer`
  - 父节点用 `fa`，不用 `father`
- **单字母例外**：仅允许标准的循环变量（`i`、`j`、`k`）、坐标（`x`、`y`）和数学占位符（`n`、`m`）。
- **禁止的命名**：不得使用无意义的单字母（如 `a`、`b`、`c` 作为状态变量）或过度冗长的全拼（如 `counter`、`visitedNodes`）。
- **核心原则**：在“见名知意”的前提下，**优先选择竞赛中约定俗成的短命名**，让代码既清晰又高效。
- **常量命名**：全大写（如 `MAX_N`）
- **函数命名**：动词开头（如 `isPrimeNumber()`）
- **适当空行**：逻辑块之间用空行分隔
- **花括号风格**：统一使用 `{` 独占一行或行尾，保持全篇一致
