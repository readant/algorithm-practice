# 并查集

## 概述

并查集（Union-Find）处理**动态连通性**问题：判断两个元素是否属于同一集合、合并两个集合。单次操作均摊近 **O(1)**（阿克曼函数反函数级别）。

核心思想：每个集合是一棵"代表元"树，`find(x)` 找到树根，`union(x, y)` 把一棵树的根挂到另一棵树下。

| 操作 | 功能 | 均摊复杂度 |
|------|------|-----------|
| find(x) | 找 x 所在集合的代表（根） | O(α(n)) ≈ O(1) |
| union(x, y) | 合并 x、y 所在集合 | O(α(n)) ≈ O(1) |
| connected(x, y) | 判断是否同集合 | O(α(n)) ≈ O(1) |

---

## 一、基础实现（路径压缩 + 按秩合并）

```cpp
class UnionFind {
    vector<int> parent;   // parent[i] = i 的父节点，根节点 parent[x] == x
    vector<int> rank;     // 树的高度（秩），用于按秩合并
public:
    UnionFind(int n) : parent(n), rank(n, 0) {
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]);   // 路径压缩：直接挂到根下
        return parent[x];
    }

    void unite(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return;
        if (rank[px] < rank[py]) swap(px, py);   // 矮树挂到高树下
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
    }

    bool connected(int x, int y) {
        return find(x) == find(y);
    }
};
```

### 两个关键优化

| 优化 | 做法 | 效果 |
|------|------|------|
| 路径压缩 | find 时把沿途节点直接挂到根下 | 把树压扁，后续查找更快 |
| 按秩合并 | 矮树挂到高树下 | 防止退化成链 |

> 两个优化**都用上**时复杂度最优；只做路径压缩也足够通过绝大多数题目。

## 二、经典应用

### 1. 连通性判断

- 判断图中有几个连通块（[P1551 亲戚](https://www.luogu.com.cn/problem/P1551)）
- 动态加边、询问连通性（网格类题目常用：把坐标映射为一维下标）

### 2. 最小生成树（Kruskal）

按边权排序，从小到大合并，若两端点已在同一集合则跳过（成环）。详见 [04-进阶算法体系/03-图论基础](../04-进阶算法体系/03-图论基础（图存储-并查集-最短路-最小生成树）.md)。

### 3. 等价类 / 关系传递

- 等式约束（[P1955 程序自动分析](https://www.luogu.com.cn/problem/P1955)）
- 朋友圈合并

## 三、进阶变体（了解即可）

- **带权并查集**：`parent` 之外维护"到根的距离/权值"，用于奇偶性、相对关系题目（[P1196 银河英雄传说](https://www.luogu.com.cn/problem/P1196)）
- **可撤销并查集**：支持回退操作，用于离线分治题目
- **反集**：并查集存"敌人关系"（[P1892 团伙](https://www.luogu.com.cn/problem/P1892)）

---

## 易错点

1. **路径压缩后仍要 find**：每次 union/connected 前都调用 `find`，不能直接比较 `parent[x]`（压缩前 parent 可能不是根）。
2. **unite 前检查同集合**：`px == py` 直接返回，否则可能死循环或错误合并。
3. **下标映射**：网格坐标 `(i, j)` 转一维下标 `i * m + j` 时注意边界，防止越界。
4. **秩的含义**：`rank` 是"合并时的优化信息"，不代表压缩后的真实高度，不要用它做别的判断。
5. **find 递归深度**：极端情况（不按秩合并）可能栈溢出，可用迭代版 find 替代。
