# 数组的三种模型

> 洛谷 [#103 入门4 数组](https://www.luogu.com.cn/training/103) 共 20 题。
> 表面五花八门，解法只有三个模型。**先认出属于哪一个，再动手。**

| 模型 | 数组下标是 | 数组元素是 | 典型题 |
| :-- | :-- | :-- | :-- |
| **桶（映射统计）** | 数值本身 | 出现次数 | P1554 梦中的统计、P2550 彩票摇奖 |
| **状态标签（布尔映射）** | 位置 / 编号 | 状态 0 或 1 | P1047 校门外的树、P1161 开灯、P5729 工艺品 |
| **模拟位移（坐标搬运）** | 位置 | 数据本体 | P1427 倒序、P1789 插火把、P5731 蛇形方阵 |

## 一、核心算法模型

### 1. 桶模型（映射统计）：数值即下标

#### 1.1 核心思想：为什么敢"拿数值当下标"

假设要比 n 个数里「x 出现了几次」。三种做法：

| 做法 | 预处理 | 单次查询 | 空间 | 什么时候能用 |
| :-- | :-- | :-- | :-- | :-- |
| 每次遍历一遍 | 无 | O(n) | O(n) | 查询次数很少 |
| 排序 + 二分 | O(n log n) | O(log n) | O(n) | 值域大到开不了数组 |
| **桶** | O(n) | **O(1)** | O(值域) | **值域不大**（关键前提） |

桶的本质：**把"查"变成"直接访问"**，用空间换时间。代价是数组大小必须覆盖整个值域。

#### 1.2 前提：值域决定了你能不能开这个桶

| 值域上限 | `int` 数组大小 | 大致内存 | 结论 |
| :-- | :-- | :-- | :-- |
| 10⁵ | 100 KB | 可忽略 | 放心用 |
| 10⁶ | 4 MB | 小事 | 放心用 |
| 10⁷ | 40 MB | 有点大 | 能用，但注意洛谷 128 MB 的题还有别的空间开销 |
| 10⁸ 以上 | 400 MB+ | 爆 | **不能用桶**，换 `map` 或排序 |

**值域写在哪看？** 题目里的「数据范围」：`0 ≤ aᵢ ≤ 1000` 这种就是值域。
**不是数据个数 n，是数值本身能到多大。**

#### 1.3 标准写法

```cpp
#include <iostream>
using namespace std;

const int MAXV = 1000;          // 值域上限
int cnt[MAXV + 1] = {0};        // 多开 1 个，防止访问 cnt[MAXV] 越界

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        cnt[x]++;               // 数字 x 的抽屉 +1
    }
    return 0;
}
```

#### 1.4 四种变体

**变体 A：计数桶**——数出现几次（上面就是）

**变体 B：布尔桶**——只关心"有没有出现过"，不关心几次

```cpp
bool vis[MAXV + 1] = {false};
vis[x] = true;                  // 出现过就打勾
```

> 什么时候用 `bool`：只问存在性。省一半空间，也更不容易被误解成"次数"。

**变体 C：去重 + 天然升序输出**——桶的下标本身就是有序的

```cpp
for (int i = 0; i <= MAXV; i++) {
    if (cnt[i] > 0) cout << i << " ";   // 从小到大，自动去重
}
```

**变体 D：桶计数排序**——按出现次数把数原样铺开

```cpp
for (int i = 0; i <= MAXV; i++) {
    for (int j = 0; j < cnt[i]; j++) {
        cout << i << " ";       // i 打印 cnt[i] 次
    }
}
```

> 这就是「计数排序」的全部内容，时间复杂度 O(n + 值域)。**值域小时比 `sort` 还快。**

#### 1.5 例题拆解：P1554 梦中的统计

**题意**：给两个数 m、n，统计 m 到 n 之间所有整数里，数字 0~9 各出现了几次。

**为什么是桶模型**：要统计的只有 10 种东西（数字 0-9），天然是个大小为 10 的桶。

**拆位是关键**：一个数 `x` 的每一位怎么拿出来？

```cpp
while (x > 0) {
    cnt[x % 10]++;              // 取个位
    x /= 10;                    // 砍掉个位
}
```

**三个必须注意的点**：

1. **`x = 0` 时上面的循环一次都不进**，所以 0 不会被统计到。
   如果区间含 0，要单独处理，或者用 `do-while`。
2. **不能直接用 `x` 循环**，循环变量被改坏了。要复制一份：
   `int t = x; while (t > 0) { ... }`
3. `m` 可能大于 `n`，先交换。

**完整骨架**：

```cpp
int cnt[10] = {0};
for (int x = m; x <= n; x++) {
    int t = x;
    if (t == 0) cnt[0]++;       // 单独处理 0
    while (t > 0) {
        cnt[t % 10]++;
        t /= 10;
    }
}
```

#### 1.6 这个模型的边界与坑

| 坑 | 现象 | 原因 | 解决 |
| :-- | :-- | :-- | :-- |
| 数组开小 | RE / 答案错 | 值域 1000 却只开 `cnt[1000]`，访问 `cnt[1000]` 越界 | 一律 `MAXV + 1`，再多留 5 |
| 值变成负数 | RE | 负数不能当下标 | 加偏移：`cnt[x + 1000]++`，查的时候也减回来 |
| 多组数据忘清空 | 第 2 组答案偏大 | 上一组的计数还留着 | 每组开头 `memset(cnt, 0, sizeof(cnt))` 或重新声明 |
| 把 n 当值域 | 数组开得过大或过小 | 混淆了"数据个数"和"数值上限" | 看题目的数据范围，不是看输入行数 |

### 2. 状态标签模型（布尔映射）：灯泡开关

#### 2.1 和桶模型的区别（最容易混的一处）

| | 桶模型 | 状态标签 |
| :-- | :-- | :-- |
| 下标代表 | **数值本身** | **位置 / 编号 / 坐标** |
| 值代表 | 出现**几次** | 有没有被处理（0/1） |
| 回答的问题 | "x 出现了几次" | "这个位置被覆盖了吗" |
| 典型 | P1554 数位统计 | P1047 区间砍树 |

一句话：**桶关心"几个"，标签关心"有没有"。**

#### 2.2 核心思想

想象一排路灯。数组不存亮度数值，只存**亮或灭**。改状态就是"把这段区间全点亮"。

#### 2.3 标准写法：单点标记

```cpp
int st[1005] = {0};            // 0 = 未处理
st[i] = 1;                     // 处理过第 i 个位置
if (st[i] == 0) { /* 还没处理 */ }
```

#### 2.4 三种变体

**变体 A：区间标记（暴力版）**

```cpp
// 把 [u, v] 全部标为 1
for (int i = u; i <= v; i++) st[i] = 1;
```

单次 O(区间长度)。**如果区间很多、值域很大，这会 TLE**——那时要换差分（见第 08 块）。

**变体 B：区间翻转（异或）**——P1161 开灯

每次都按开关，状态取反：

```cpp
st[i] ^= 1;                    // 0 变 1，1 变 0
```

> 用 `1 - st[i]` 也对，但 `^= 1` 更快也更符合"翻转"的语义。

**变体 C：多状态标记**——不止两种状态

```cpp
// 0 = 未访问  1 = 访问中  2 = 已完成
st[x] = 1;
```

图论里的"三色标记"就是这个（判环时用）。

#### 2.5 例题拆解：P1047 校门外的树

**题意**：马路长 L（0 到 L 每米一棵树），修 M 段地铁，每段覆盖 [u, v]，问还剩几棵树。

**为什么是标签模型**：每个位置只有"被砍 / 没被砍"两种状态。

**三步**：

1. 开 `int tree[L+1]`，全 0（表示树还在）
2. 每段区间，`for (i = u; i <= v; i++) tree[i] = 1`
3. 最后数 `tree[i] == 0` 的个数

```cpp
int tree[10005] = {0};
for (int k = 0; k < m; k++) {
    int u, v;
    cin >> u >> v;
    for (int i = u; i <= v; i++) tree[i] = 1;
}
int left = 0;
for (int i = 0; i <= L; i++) {
    if (tree[i] == 0) left++;
}
```

**复杂度**：O(M × L)。本题 L ≤ 10000、M ≤ 100，约 10⁶ 次，安全。
**如果 L 到 10⁹ 就不能这么写了**，要换差分 + 离散化。

#### 2.6 边界与坑

| 坑 | 说明 |
| :-- | :-- |
| 区间端点含不含 | 题目说"从 u 到 v 都覆盖"，一般含两端，写 `i <= v` |
| 下标起点 | 本题从 0 开始，循环要 `i = 0`；很多题从 1 开始，看清题意 |
| 与桶混用 | "统计每个数值出现次数"用桶；"标记每个位置状态"用标签，别搞反 |

### 3. 模拟位移模型：坐标搬运工

#### 3.1 核心思想

数组内容一个都不改，**改的是访问顺序**。三件事：倒着看、转着看、绕着走。

#### 3.2 三个子类

**子类 A：逆向访问**——倒序输出

```cpp
for (int i = n - 1; i >= 0; i--) cout << a[i] << " ";
```

**子类 B：循环移动**——整体左移 k 位 / 右移 k 位

```cpp
// 右移 k 位（k 可能大于 n，先取模）
k %= n;
for (int i = n - k; i < n; i++) cout << a[i] << " ";
for (int i = 0; i < n - k; i++) cout << a[i] << " ";
```

> 不要求原地的话，**直接换输出顺序**最省事，不用真的搬数组。

**子类 C：二维按方向走**——方向数组

```cpp
int dx[] = {0, 0, 1, -1};      // 右 左 下 上
int dy[] = {1, -1, 0, 0};

int nx = x + dx[d];
int ny = y + dy[d];
if (nx < 0 || ny < 0 || nx >= n || ny >= m) continue;   // 越界就跳过
```

八方向就再加四个对角：

```cpp
int dx8[] = {-1, -1, -1, 0, 0, 1, 1, 1};
int dy8[] = {-1, 0, 1, -1, 1, -1, 0, 1};
```

#### 3.3 例题拆解：P5731 蛇形方阵

**题意**：把 1 到 n² 按蛇形（顺时针螺旋）填进 n×n 矩阵。

**两个循环变量**：当前位置 `(x, y)` 和当前方向 `d`。

**转向条件有两个**（缺一不可）：

1. 下一步**出界**
2. 下一步**已经填过了**（值不为 0）

```cpp
int a[15][15] = {0};
int dx[] = {0, 1, 0, -1};      // 右 下 左 上（顺时针）
int dy[] = {1, 0, -1, 0};

int x = 0, y = 0, d = 0;
for (int k = 1; k <= n * n; k++) {
    a[x][y] = k;
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 0 || ny < 0 || nx >= n || ny >= n || a[nx][ny] != 0) {
        d = (d + 1) % 4;       // 转向
        nx = x + dx[d];
        ny = y + dy[d];
    }
    x = nx;
    y = ny;
}
```

**为什么方向数组要按顺时针写**：`(0,1)→(1,0)→(0,-1)→(-1,0)` 依次是右、下、左、上，
`d = (d+1) % 4` 就自然转一圈。**顺序写错就变成逆时针**，答案全反。

**输出格式**：题目要求每个数占 3 个字符宽度 →

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) cout << setw(3) << a[i][j];
    cout << "\n";
}
```

（`setw` 需要 `#include <iomanip>`）

#### 3.4 边界与坑

| 坑 | 说明 |
| :-- | :-- |
| 先填再走 vs 先走再填 | 上面是"先填再判方向"，如果写成"先走再填"会漏掉起点 |
| 数组多开一圈 | 网格题多开 2 行 2 列，可以省掉一半越界判断 |
| 方向顺序 | 必须和题目要求的旋转方向一致，写完先手推 n=3 |
| 循环终止 | 填满 `n*n` 次就停，不要用坐标判断 |

### 怎么选

1. **要数出现几次**（下标=数值） → 桶模型
2. **要记录位置被没被处理**（下标=位置） → 状态标签
3. **要改变顺序 / 按方向走** → 模拟位移

三者会叠用：P1047 = 标签 + 最后计数；BFS = 标签（`vis`）+ 位移（方向数组）。

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **全局数组** | 定义在 `main` 外面 | 自动清零，且能开得比局部大得多（局部约 1-2 MB 就爆栈） |
| **多开 5–10 个单位** | 题目要 1000 就开 1010 | 挡住 0/1 起下标混乱导致的边界错误 |
| **`sort(a, a + n)`** | `<algorithm>` | 需要排序时首选，不用手写 |
| **`long long` 接累加** | `long long sum = 0;` | 累加会超 `int`（约 21 亿） |
| **`memset` 清空** | `<cstring>`，`memset(a, 0, sizeof(a))` | 多组数据的必备动作 |

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;

const int MAXN = 1005;
int a[MAXN];                   // 全局：多开 5 个，默认全 0
long long sum = 0;             // 累加用 long long
```

## 三、初学者必踩的坑

**坑 1：随机数惊魂**

- 现象：每次运行结果不一样，或输出莫名其妙的负数
- 原因：**局部数组没初始化**，里面是内存里残留的垃圾值
- 解决：定义成全局，或写 `int a[100] = {0};`

**坑 2：越界访问（RE 元凶）**

- 现象：洛谷报 RE，本地直接闪退
- 原因：`for (i = 0; i <= n; i++)` 访问了 `a[n]`，而合法下标只到 `n-1`
- 解决：循环一律 `i < n`；数组一律多开

**坑 3：小桶装大水（类型溢出）**

- 现象：正数范围题里算出负数
- 原因：累加超过 `int` 上限
- 解决：求和用 `long long`；乘法先转 `1LL * a * b`

**坑 4：多组数据不清空**

- 现象：第 1 组对，第 2 组答案偏大且越来越大
- 原因：上一组的数据还留在数组里
- 解决：每组开头 `memset(a, 0, sizeof(a))`

## 四、学习建议

按 5 小时推进，一题一个模型，做完立刻回看对应小节：

| 时段 | 题目 | 练哪个模型 | 验收标准 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | P1427 小鱼的数字游戏 | 模拟位移（逆向） | 能处理"读到 0 停"的不定长输入 |
| 第 2 小时 | P1047 校门外的树 | 状态标签 | 能说清"0 和 1 各代表什么" |
| 第 3 小时 | P1554 梦中的统计 | 桶（拆位） | 能正确统计 0，不漏前导位 |
| 第 4 小时 | P1789 插火把 | 位移 + 标签（二维） | 边界写对，不越界 |
| 第 5 小时 | P5731 蛇形方阵 | 位移（方向数组） | 手推 n=3 能对上，转向条件不缺 |

**每题的验收动作**（不要只看"过了"）：

1. 说出这题属于哪个模型，**为什么不是另外两个**
2. 说出复杂度，以及数据范围放大 10 倍还能不能过
3. 记**一条**自己真踩过的坑到题解目录，不要抄整段题解
