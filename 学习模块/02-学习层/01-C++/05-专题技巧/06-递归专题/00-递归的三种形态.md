# 递归

> 递归就是**俄罗斯套娃**：把大问题拆成一个一模一样的小问题，一直拆到最简单的那层（出口），
> 再把结果一层层传回来。

| 类型 | 长什么样 | 典型 | 什么时候用 |
| :-- | :-- | :-- | :-- |
| **线性递归** | 自己调自己**一次** | 阶乘、斐波那契（朴素） | 每一步只依赖"上一个" |
| **多路递归** | 自己调自己**两次以上** | 汉诺塔、树的遍历 | 大问题能拆成**两半或几份**分别解决 |
| **分治递归** | 拆成两半，分别算，再合并 | 归并排序、快排 | 子问题互不重叠 |

---

## 一、核心算法模型

### 1. 套娃模型：出口 + 关系

#### 1.1 两步走战略

写递归**只有两句**，顺序不能反：

1. **写出口（刹车）**——`if (最简单的情况) return 直接的结果;`
2. **写关系（递推）**——`return 用更小规模的自己算出来;`

以阶乘为例：

```cpp
long long fact(int n) {
    if (n <= 1) return 1;             // 1. 出口：1! 就是 1，不用再拆
    return 1LL * n * fact(n - 1);     // 2. 关系：n! = n × (n-1)!
}
```

#### 1.2 为什么这样写是对的

数学上叫**归纳法**，写代码时你只需要相信两件事：

1. **最底层能算出结果**（出口正确）
2. **如果 n-1 层的结果是对的，那 n 层也能算对**（关系正确）

只要这两条成立，**所有层都对**。你不需要在脑子里模拟 100 层的展开。

#### 1.3 调用栈：程序到底怎么跑的

以 `fact(3)` 为例，程序分两个阶段：

```
进去（压栈，每层都还没算完）
  fact(3) → 要算 3 * fact(2)，先等
    fact(2) → 要算 2 * fact(1)，先等
      fact(1) → 出口，返回 1          ← 最底层
回来（弹栈，倒着把没做完的算完）
    fact(2) 拿到 1，算出 2 * 1 = 2
  fact(3) 拿到 2，算出 3 * 2 = 6
```

**关键点**：每层都有**自己的 `n`**。`fact(3)` 里的 `n` 和 `fact(2)` 里的 `n` 是两个不同的变量，
互不干扰。这就是"局部变量"的意义。

#### 1.4 例题拆解：P5739 计算阶乘

**题意**：给 n，求 n!。

**这题的意义**：理解"出口 + 返回"的最小例子。

```cpp
#include <iostream>
using namespace std;

long long fact(int n) {
    if (n <= 1) return 1;             // 注意是 <=，不是 ==
    return 1LL * n * fact(n - 1);
}

int main() {
    int n;
    cin >> n;
    cout << fact(n) << "\n";
    return 0;
}
```

**两个易错点**：

1. **出口写 `n <= 1` 而不是 `n == 1`**。万一输入 0，`n == 1` 永远不成立，会无限递归到栈溢出。
2. **`1LL *` 不能省**。`n * fact(n-1)` 里 `fact` 返回 `long long`，
   但 `n` 是 `int`，某些编译器会先按 `int` 算。写 `1LL *` 强制提升。

### 2. 汉诺塔模型：相信"黑盒"

#### 2.1 核心思想

三根柱子 A、B、C，n 个盘子从 A 移到 C，每次只能移一个、大盘不能压小盘。

**不要试图在脑子里模拟每一步。** 你只需要相信：

> 如果我能把上面 n-1 个盘子移到 B，那剩下的就很简单了。

#### 2.2 三步逻辑

1. 把上面 **n-1 个** 从 A 移到 B（借助 C）——**交给递归**
2. 把**最大的那个**从 A 移到 C——**手动一步**
3. 把 n-1 个从 B 移到 C（借助 A）——**交给递归**

```cpp
void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;                        // 出口：没有盘子就不用动
    hanoi(n - 1, from, to, via);               // 1. n-1 个 → via
    cout << from << " -> " << to << "\n";      // 2. 最大的直接搬
    hanoi(n - 1, via, from, to);               // 3. n-1 个 → to
}
```

**参数顺序为什么要这样传**：注意第 1 步和最后一步里，`via` 和 `to` 的位置是**交换**的——
因为两次"借助的中转柱"不一样。这是这题最容易写错的地方。

**调用次数**：`2ⁿ - 1` 次。n=20 就是一百万次，**所以这题 n 一般不超过 20**。

#### 2.3 什么时候能套这个模型

当你发现**大问题的解决步骤里，包含了一个规模更小的相同操作**时：

- 树的遍历（左子树、根、右子树）
- 快速排序（左边排好、右边排好）
- 归并排序（左右各排好、再合并）

### 3. 分治递归：拆成两半

```cpp
// 快速排序的递归骨架
void quickSort(int a[], int l, int r) {
    if (l >= r) return;                // 出口：区间里 0 或 1 个元素
    int p = partition(a, l, r);        // 把区间分成两半
    quickSort(a, l, p - 1);            // 左半
    quickSort(a, p + 1, r);            // 右半
}
```

**和套娃模型的区别**：套娃是"一次只小 1"，分治是"一次小一半"。
所以分治的递归深度是 **log n**，套娃是 **n**。

---

### 怎么选

1. **每一步只依赖上一个** → 线性递归（阶乘、斐波那契）
2. **大问题能拆成几份分别处理** → 多路递归（汉诺塔、树的遍历）
3. **能对半分** → 分治（排序、二分）
4. **规模很大且会重复计算** → 别用朴素递归，改递推或记忆化（见第 09 块）

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **先写出口** | 函数第一行就写 `if (...) return ...;` | 忘写就是死循环 + 栈溢出 |
| **相信黑盒** | 不要模拟每一层 | 模拟超过 3 层脑子就不够用了 |
| **纸上画递归树** | n=3 时把调用画出来 | 新手别空想，画一遍就通了 |
| **`long long` 返回** | 阶乘/累加类 | 递归结果很容易超 `int` |

## 三、初学者必踩的坑

**坑 1：死循环 / 程序崩溃（Segmentation Fault）**

- 现象：程序直接崩，没有任何输出，或输出一堆乱码
- 原因：**忘记写出口**，或出口条件永远不成立（比如该写 `n <= 1` 却写了 `n == 1`，输入 0 时永远到不了）
- 解决：先写出口再写逻辑；检查"最坏情况下能不能走到出口"

**坑 2：算得慢 / 超时（TLE）**

- 现象：n 稍微大一点就算不出来
- 原因：**重复劳动**。朴素斐波那契里，`f(5)` 会调用 `f(3)` 两次、`f(2)` 三次……
  总调用次数是**指数级**的
- 解决：n 大就改用循环（递推）；或者加记忆化（见后）

> 斐波那契 `f(40)` 的朴素递归要算约 **1 亿次**，而循环只要 **40 次**。这是最典型的对比。

**坑 3：变量值乱套**

- 现象：递归里打印出来的变量和预期不符
- 原因：分不清全局变量和局部变量。**每一层递归都有自己的局部变量**
- 解决：中间状态用局部变量；只有确实要跨层共享的才用全局

**坑 4：递归太深，栈溢出**

- 现象：n 到几万时崩，但逻辑没问题
- 原因：每层调用都占栈空间，默认栈只有几 MB
- 解决：改成循环（递推）；或加大栈（比赛不推荐）

## 四、学习建议

按 5 小时推进：

| 时段 | 题目 | 练什么 | 验收标准 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | P5739 计算阶乘 | 出口 + 返回 | 能在纸上画出 n=3 的调用过程 |
| 第 2 小时 | B2064 斐波那契 | 多路递归 | 能说出为什么它慢，算过几次 |
| 第 3 小时 | 08.06 汉诺塔 | 相信黑盒 | 不模拟每一步，只写三步 |
| 第 4 小时 | 手写递归求数组和 / 求最大值 | 分治思想 | 能把区间对半拆 |
| 第 5 小时 | 复习：把三个例题默写一遍 | 全部 | 不看笔记能写出汉诺塔 |

**每题验收动作**：

1. 说出这题的**出口**是什么，"最简单的情况"在哪
2. 说出**每层小多少**（小 1 还是小一半）
3. 能在纸上画出 n=3 的调用树，并标出每层的变量值

> 递归是"先苦后甜"。刚开始画图很难受，但看透"套娃"规律后，写代码比循环快得多。
