# 贪心

> 贪心的本质是**只顾眼前，不看未来**：每一步都选当前看来最好的，并且相信这样能得到全局最优。
> 能这么做的前提是问题满足「**贪心选择性质**」——局部最优能推出全局最优。

| 类型 | 排序依据 | 典型题 |
| :-- | :-- | :-- |
| **区间调度** | 按**结束时间**升序 | 最多能参加几个活动 |
| **排序不等式** | 按**耗时**升序 | 排队打水，总等待时间最短 |
| **最值配对** | 先排序，再最重配最轻 | 乘船问题、两数之和 |

---

## 一、核心算法模型

### 1. 三步走：定策略 → 排序 → 迭代

**贪心题 90% 的第一步都是 `sort`。** 真正的难点是**按什么排序**。

```
① 确定策略：按什么排？（结束时间？耗时？价值？）
② 排序：sort 一下
③ 迭代：从头到尾扫一遍，边扫边决策
```

### 2. 例题 1：区间调度（最常考）

**题意**：n 个活动，每个有开始时间 `s` 和结束时间 `e`。同一时间只能做一个，问最多能做几个。

**三种排序方式，哪种对**：

| 排序依据 | 反例 | 结论 |
| :-- | :-- | :-- |
| 按**开始时间**升序 | `[1,100] [2,3] [4,5]` → 选第一个就只剩 1 个，实际能 2 个 | ❌ |
| 按**时长**升序 | `[1,10] [2,3] [3,4]` → 先选短的 `[2,3]`，反而卡住 | ❌ |
| 按**结束时间**升序 | 无 | ✅ |

**为什么按结束时间**：结束得越早，留给后面活动的时间就越多。

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

struct Activity {
    int start, end;
};
Activity a[100005];

bool cmp(const Activity& x, const Activity& y) {
    return x.end < y.end;            // 按结束时间升序
}

int main() {
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i].start >> a[i].end;
    sort(a, a + n, cmp);

    int cnt = 0;
    int lastEnd = -1;                // 上一个选中活动的结束时间
    for (int i = 0; i < n; i++) {
        if (a[i].start >= lastEnd) { // 不冲突
            cnt++;
            lastEnd = a[i].end;
        }
    }
    cout << cnt << "\n";
    return 0;
}
```

> `a[i].start >= lastEnd` 里的 `>=` 还是 `>`，取决于题目**允不允许端点重合**。
> "一个结束后立刻开始下一个"用 `>=`；"中间必须留间隔"用 `>`。

### 3. 例题 2：打水排队（排序不等式）

**题意**：n 个人排队打水，每人耗时 tᵢ，怎么排能让**所有人等待时间之和**最小？

**策略**：**快的先打**。

**为什么**：第一个人的耗时会被后面**所有人**重复等待。让小的数重复次数多，总和才小。

```
t = {1, 2, 5}
顺序 1→2→5：
  第 1 人打水，后面 2 人各等 1 分钟 → 1×2 = 2
  第 2 人打水，后面 1 人等 2 分钟   → 2×1 = 2
  第 3 人打水，后面没人             → 0
  总等待 = 4
```

```cpp
sort(t, t + n);                          // 升序
long long total = 0;
for (int i = 0; i < n; i++) {
    total += (long long)t[i] * (n - 1 - i);   // 第 i 个人被后面 n-1-i 个人等
}
```

> **`(n - 1 - i)` 这个系数**是这题的核心：排在前面的被等次数多。
> 也可以正向累加前缀和：`total += sum; sum += t[i];` 效果一样。

### 4. 例题 3：乘船问题（最值配对）

**题意**：n 个人过河，每船最多 2 人，限重 W，问最少几条船。

**策略**：**最重的尽量和最轻的拼**。

```cpp
sort(p, p + n);                          // 体重升序
int left = 0, right = n - 1;
int boats = 0;
while (left <= right) {
    if (left < right && p[left] + p[right] <= W) {
        left++;                          // 最轻的能陪最重的一起走
    }
    right--;                             // 最重的上船（不管有没有伴）
    boats++;
}
```

**为什么这样最优**：如果最重的人能和**最轻**的人拼船，那换成任何其他人都更重，更不可能拼成。
所以"能和最轻的拼就拼"，不会错过更好的选择。

### 5. 什么时候贪心是错的

这是最容易踩的坑：**贪心看起来很合理，但答案是错的**。

| 场景 | 贪心为什么错 | 该用什么 |
| :-- | :-- | :-- |
| **0/1 背包** | 按"性价比"排序，但物品不可分割，装不满会浪费 | 动态规划 |
| **面值奇怪的找零** | 面值 {1,3,4} 找 6 元，贪心给 4+1+1（3 枚），实际 3+3（2 枚） | 动态规划 |
| **需要全局权衡的路径** | 每一步都选最近的，可能走进死路 | 搜索 / 最短路 |

**判据**：如果题目允许"**分割**"（如散装货物、液体），贪心通常对；
如果物品**不可分割**且要"装得最满"，那多半是 DP。

### 怎么选

1. **一堆区间，选最多不重叠的** → 按结束时间排序
2. **有先后顺序影响总代价** → 按耗时/代价排序，排在前面的被重复计算多次
3. **两两配对、有容量限制** → 排序后双指针，最重的配最轻的
4. **物品不可分割 + 要最大化总价值** → 不是贪心，是 DP

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **`sort`** | 贪心的第一步 | 90% 的贪心题都要排序 |
| **自定义 `cmp`** | 按结构体某个字段排 | 区间、任务类题目必用 |
| **`long long` 累加** | `total += 1LL * x * y` | 贪心题常算总和，极易超 `int` |
| **反例法验证** | 举 3 个反例试策略 | 考场上没时间严格证明 |

```cpp
// 不确定按什么排？在纸上试三组数据，哪组策略被推翻就换
sort(a, a + n, cmp);
```

## 三、初学者必踩的坑

**坑 1：排错了关键字**

- 现象：样例过，提交 WA
- 原因：按"看起来合理"的字段排（如区间按开始时间），但那是错的
- 解决：**举反例验证**。构造一个小数据，让这个策略明显吃亏

**坑 2：总和溢出**

- 现象：答案变成负数
- 原因：n ≥ 10⁵ 时，累加很容易超 `int` 的 21 亿
- 解决：**只要看到求和，就用 `long long`**

**坑 3：边界符号写反**

- 现象：区间调度少了或多了 1
- 原因：`>=` 和 `>` 混用（端点能否重合）
- 解决：读题确认"结束后能否立刻开始"

**坑 4：用贪心解了该用 DP 的题**

- 现象：思路清楚，代码也对，就是 WA
- 原因：问题本身不满足贪心选择性质
- 解决：看到"物品不可分割""要最优组合"就警惕，先想 DP

**坑 5：浮点排序精度**

- 现象：性价比排序后结果偶尔错
- 原因：`double` 比较有精度误差
- 解决：用交叉相乘代替除法：`a.v * b.w > b.v * a.w`

## 四、学习建议

按 5 小时推进：

| 时段 | 题目 | 练什么 | 验收标准 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | 区间调度模板 | 按结束时间排序 | 能构造反例说明为什么不能按开始时间 |
| 第 2 小时 | 打水排队 | 排序不等式 | 能解释 `(n-1-i)` 这个系数 |
| 第 3 小时 | 乘船问题 | 双指针贪心 | 能说清"最重配最轻"为什么不会错过最优 |
| 第 4 小时 | 找零问题（面值 {1,3,4}） | 识别贪心失效 | 能举出贪心错的例子 |
| 第 5 小时 | 蓝桥真题：翻硬币 / 付账问题 | 综合 | 能独立判断该用贪心还是 DP |

**每题验收动作**：

1. 说出**按什么排序**，以及为什么不能按别的排（**给出反例**）
2. 说出这题的答案是"最多""最少"还是"最优"
3. 说出结果会不会超 `int`

> 考场上没时间写严格证明。用**验证法**：手推 3~5 组数据，策略不被推翻就大胆写。
