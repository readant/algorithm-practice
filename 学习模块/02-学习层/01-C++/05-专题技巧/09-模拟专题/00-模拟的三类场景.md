# 模拟

> 模拟题不难，难在**细心**。它没有任何高深算法，就是**题目怎么说，代码就怎么做**。
> 但正因如此，别人写 20 行，你可能写 80 行，还错在某个 "如果……则……" 上。

| 类型 | 长什么样 | 典型 | 关键 |
| :-- | :-- | :-- | :-- |
| **迭代变换** | 按规则反复变形，直到某个条件 | 冰雹数、奇怪的数列 | 终止条件写对 |
| **网格行走** | 在一个矩阵里按规则移动 | 走迷宫、蛇形填数 | 边界判断 |
| **过程/队列模拟** | 有多个实体按规则交互 | 拉马车、排队问题 | 状态用容器存住 |

---

## 一、核心算法模型

### 1. 迭代变换：一直变，直到停

**核心**：有一个数或一串数，按固定规则不断变化，问变化几次 / 变成什么。

**必写三件事**：

1. **初始状态**（从哪开始）
2. **变换规则**（怎么变）
3. **终止条件**（什么时候停）

#### 例题：冰雹猜想

**题意**：给 n。若 n 是偶数就除以 2，若 n 是奇数就乘 3 加 1，问多少步变成 1。

```cpp
int steps = 0;
while (n != 1) {                 // 终止条件
    if (n % 2 == 0) n /= 2;      // 规则一
    else n = n * 3 + 1;          // 规则二
    steps++;
}
cout << steps << "\n";
```

**三个要注意的地方**：

1. **`n` 用 `long long`**。虽然最终会回到 1，但中间过程可能超过 `int`（n 到 10⁹ 时乘 3 加 1 会爆）
2. **终止条件不能是 `n > 1`**。如果初始 n=1，循环一次都不进，答案应该是 0 步
3. **`n` 可能被改成 0 或负数**（输入不合法时），要保证循环能出来

#### 变体：生成一个序列

**例**：`a[1]=1, a[2]=11, a[3]=21`，规则是"读上一项：一个 1、两个 1、一个 2"，问第 n 项。

这种题的关键是**把规则翻译成循环**：

```cpp
// 从 s 生成下一项：数连续相同字符的个数
string nxt;
for (int i = 0; i < (int)s.size(); ) {
    int j = i;
    while (j < (int)s.size() && s[j] == s[i]) j++;   // 数相同字符有几个
    nxt += to_string(j - i);                          // 个数
    nxt += s[i];                                      // 字符
    i = j;                                            // 跳到下一个不同的
}
```

> **双指针数连续段**是这类题的通用手法：`i` 定起点，`j` 往后探，`j-i` 就是长度。

### 2. 网格行走：按规则在矩阵里动

**核心**：有一个网格，某个位置上有东西，按规则向左/右/上/下移动，问最终位置或路径。

**必写三件事**：

1. **当前位置** `(x, y)`
2. **方向** `d`（配方向数组）
3. **每一步的判断**：越界？撞墙？重复？

```cpp
int dx[] = {0, 0, 1, -1};       // 右 左 下 上
int dy[] = {1, -1, 0, 0};

while (true) {
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 0 || ny < 0 || nx >= n || ny >= m) break;   // 越界就停
    if (g[nx][ny] == 1) break;                           // 撞墙就停
    x = nx; y = ny;                                      // 走这一步
}
```

#### 例题：蛇形填数（P5731）

按顺时针方向往 n×n 矩阵里填 1 到 n²，碰到边界或已填就转向。

**关键**：转向条件有**两个**，缺一不可。

```cpp
int d = 0;                                  // 当前方向
for (int k = 1; k <= n * n; k++) {
    a[x][y] = k;
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 0 || ny < 0 || nx >= n || ny >= n || a[nx][ny] != 0) {
        d = (d + 1) % 4;                    // 转向
        nx = x + dx[d];
        ny = y + dy[d];
    }
    x = nx; y = ny;
}
```

> `a[nx][ny] != 0` 这个条件不能少——没有它，走到已经填过的格子时会覆盖。

### 3. 过程/队列模拟：多个实体按规则交互

**核心**：不是一个人走，而是**一堆东西排队、进出、交互**。典型是"拉马车"（牌堆）这类。

**必写三件事**：

1. **用什么容器存状态**（`queue` / `vector` / 多个数组）
2. **每一步谁动**（轮转？优先级？）
3. **什么时候结束**

```cpp
#include <queue>

queue<int> q;
for (int i = 1; i <= n; i++) q.push(i);      // 初始队列

while (!q.empty()) {
    int cur = q.front();
    q.pop();
    // 按规则处理 cur，可能要再 push 回去
    q.push(cur);
    if (/* 终止条件 */) break;
}
```

> 这类题最容易写乱，建议**先在纸上列 5 步**，看清每一步"谁出、谁进、什么变了"。

### 怎么选

1. **一个数反复按规则变** → 迭代变换（重点写终止条件）
2. **在格子里按方向走** → 网格行走（重点写边界）
3. **多个东西排队、进出、交互** → 过程模拟（重点选容器）

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **先写伪代码** | 在纸上列步骤，再动手 | 模拟题的错误 80% 出在"想漏了一步" |
| **数组存状态** | 地图、访问标记、队列 | 模拟要靠状态驱动 |
| **函数拆步骤** | 每个规则一个函数 | 否则主函数会涨到 200 行 |
| **`long long`** | 数值变换类 | 中间过程容易超 `int` |

```cpp
// 反例：全部塞在 main 里
// 正例：一条规则一个函数
bool canMove(int x, int y) { /* 边界 + 撞墙判断 */ }
void moveStep()            { /* 走一步 */ }
void printMap()            { /* 输出当前状态 */ }
```

## 三、初学者必踩的坑

**坑 1：样例过了，提交只有部分分**

- 现象：样例对，但 OJ 上部分通过
- 原因：**边界条件漏了**。模拟题通常有大量 "如果……则……"，比如"恰好为 0""到达边界""空输入"
- 解决：把题目里每一个条件**逐条对照代码**打勾；自己造 3 组边界数据试

**坑 2：超时（TLE）**

- 现象：逻辑正确但跑不动
- 原因：**无效模拟**。按字面意思一路模拟，步数可能是 10⁹
- 解决：找循环节（序列会不会周而复始），或者用数学公式跳过一段

> 例：冰雹数如果 n 到 10⁷，可以加一个"已经算过的数直接查表"（记忆化）。

**坑 3：代码越写越长，最后自己看不懂**

- 现象：改一处 bug 引出三处新 bug
- 原因：所有逻辑塞在 `main` 里，变量有 20 个
- 解决：**一条规则一个函数**，主函数只负责读入和调用

**坑 4：模拟了错的规则**

- 现象：答案和样例对不上，但代码"逻辑自洽"
- 原因：读题时把"前"当成"后"、把"开区间"当成"闭区间"
- 解决：**用样例手推一遍**，把每一步的变量值写下来，和代码输出对比

## 四、学习建议

按 5 小时推进：

| 时段 | 题目 | 练什么 | 验收标准 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | 冰雹猜想（P5727） | 迭代变换 | 终止条件正确，n=1 时输出 0 |
| 第 2 小时 | 奇怪的数列 | 序列生成 | 能用双指针数连续段 |
| 第 3 小时 | P5731 蛇形方阵 | 网格行走 | 转向两个条件都不缺 |
| 第 4 小时 | 矩形面积（蓝桥） | 坐标几何 | 能处理重叠与相交 |
| 第 5 小时 | 拉马车（蓝桥） | 过程模拟 | 能说清每一步"谁出谁进" |

**每题验收动作**：

1. **先在纸上模拟 3 步**，再动手写代码
2. 列出题目里**所有** "如果……则……"，逐条对照代码
3. 自己造 3 组数据：最小、最大、边界

> 模拟题不难，难在"细心"。**不要急着动手写，先在脑子里把过程走一遍。**
