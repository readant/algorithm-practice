# C++ 数据结构：怎么选容器

> 这一篇不教 STL 怎么用——那是 [A1-STL 工具箱](../../02-数据结构/A1-STL容器与算法（工具箱）.md) 的事。
> 这里只解决一个问题：**看到题目，该拿哪个容器装数据。**

## 一、先看这张选择表

| 你要干什么 | 用什么 | 单次操作 | 头文件 |
| :-- | :-- | :-- | :-- |
| 按顺序存、按下标取 | **`vector`** | 随机访问 O(1) | `<vector>` |
| 频繁在**两端**增删 | `deque` | 两端 O(1) | `<deque>` |
| **后进先出**（括号匹配、撤销） | **`stack`** | O(1) | `<stack>` |
| **先进先出**（BFS、排队） | **`queue`** | O(1) | `<queue>` |
| 每次要取**最大/最小** | **`priority_queue`** | O(log n) | `<queue>` |
| **去重 + 有序** + 查存在 | **`set`** | O(log n) | `<set>` |
| **键 → 值** 映射、计数 | **`map`** | O(log n) | `<map>` |
| 只要 **O(1) 查存在** | `unordered_set` | 平均 O(1) | `<unordered_set>` |
| 字符序列 | **`string`** | — | `<string>` |

> 加粗的六个（`vector` / `stack` / `queue` / `priority_queue` / `set` / `map`）覆盖了
> 备赛期 95% 的场景。**先把这六个练熟，其他都是补充。**

## 二、核心模型：按"存取需求"分三类

### 1. 顺序容器：按顺序进出

**特征**：元素的顺序有意义，你是"第几个"来访问。

#### `vector`——默认选择

不确定用什么的时候，先用 `vector`。它几乎什么都能干。

```cpp
#include <vector>
using namespace std;

vector<int> v;
v.push_back(3);          // 尾部加
v.pop_back();            // 尾部删
int x = v[2];            // 随机访问 O(1)
int n = (int)v.size();   // 长度
```

**二维数组用 `vector`**（大矩阵必须这样开，否则爆栈）：

```cpp
vector<vector<int> > g(n, vector<int>(m, 0));   // n×m，全 0
g[i][j] = 1;
```

> 注意 `> >` 中间要有空格（C++11 之前会被当成右移运算符，养成习惯）。

#### `stack` / `queue`——受限制的容器

它们只允许在一端操作，故意"不好用"——正因为限制，语义才清晰。

```cpp
#include <stack>
#include <queue>

stack<int> st;
st.push(1);  st.top();   st.pop();     // 后进先出

queue<int> q;
q.push(1);   q.front();  q.pop();      // 先进先出
```

| 容器 | 语义 | 典型用途 |
| :-- | :-- | :-- |
| `stack` | 最后进的先出 | 括号匹配、单调栈、递归模拟 |
| `queue` | 最先进的先出 | BFS、模拟排队 |

> **`stack` 没有 `front()`，`queue` 没有 `top()`**。写错会编译失败，这是新手最常见的笔误。

### 2. 关联容器：按"值"来查

**特征**：你不关心它排第几，你关心"这个值在不在""这个键对应什么"。

#### `set`——去重 + 有序 + 查存在

```cpp
#include <set>

set<int> s;
s.insert(5);
s.insert(5);                    // 不会重复插入
if (s.count(5)) { ... }         // 在不在（返回 0 或 1）
s.erase(5);
// 遍历天然升序
for (set<int>::iterator it = s.begin(); it != s.end(); ++it) cout << *it;
```

**底层是平衡树**，所以插入/查找都是 O(log n)，但**自动有序**。

#### `map`——键值映射

```cpp
#include <map>

map<string, int> cnt;
cnt["apple"]++;                 // 不存在会先插入默认值 0，再 ++
if (cnt.count("apple")) { ... } // 只查不插入
```

**`[]` 和 `count()` 的区别（很重要）**：

- `cnt[key]` —— 如果 key 不存在，**会插入一个默认值 0**，然后返回它
- `cnt.count(key)` —— 只查，**不插入**

> 用 `[]` 判存在会悄悄改变容器大小。只想判断有没有，用 `count()` 或 `find()`。

### 3. 适配器：按"出队规则"选

#### `priority_queue`——每次取最值

```cpp
#include <queue>

priority_queue<int> big;                                        // 大顶堆（默认）
priority_queue<int, vector<int>, greater<int> > small;          // 小顶堆
big.push(3);
int mx = big.top();     // 最大值
big.pop();              // 弹出最大值
```

**典型用途**：Top-K（只保留最大的 k 个）、合并有序序列、Dijkstra。

> 小顶堆那行的三个模板参数不好记，直接背：`priority_queue<int, vector<int>, greater<int> >`。

### 怎么选（三问）

1. **我要按顺序访问吗？** 是 → `vector`
2. **我要按值查"在不在/对应什么"吗？** 是 → `set` / `map`
3. **我每次只要最值 / 只要按某种顺序出？** 是 → `priority_queue` / `stack` / `queue`

## 三、必须掌握的"编程利器"

| 利器 | 怎么写 | 为什么重要 |
| :-- | :-- | :-- |
| **二维 `vector`** | `vector<vector<int> > g(n, vector<int>(m, 0))` | 大矩阵必须这样开，定长数组会爆栈 |
| **范围 for** | `for (int x : v)` | 遍历更短，C++11 支持 |
| **`count()` 而非 `[]`** | 判存在用 `s.count(x)` | `[]` 会插入默认值 |
| **`size()` 转 `int`** | `(int)v.size()` | 无符号数和负数比较会出问题 |

```cpp
#include <vector>
#include <stack>
#include <queue>
#include <set>
#include <map>
#include <string>
#include <algorithm>
using namespace std;
```

## 四、初学者必踩的坑

**坑 1：`vector` 越界**

- 现象：RE 或读出垃圾值
- 原因：`v[i]` **不做边界检查**，`v.size()` 是 3 时访问 `v[3]` 不会报错，直接读脏数据
- 解决：确保 `i < v.size()`；需要检查时用 `v.at(i)`（会抛异常）

**坑 2：`map[]` 悄悄插入**

- 现象：遍历时多出一堆值为 0 的键
- 原因：`if (mp[x])` 或 `mp[x]` 读值时会自动插入
- 解决：判存在用 `mp.count(x)` 或 `mp.find(x) != mp.end()`

**坑 3：`size()` 是无符号的**

- 现象：`for (int i = 0; i < v.size() - 1; i++)` 在空容器上变成死循环
- 原因：`size()` 返回 `size_t`，`0 - 1` 绕回最大值
- 解决：先 `int n = (int)v.size();`

**坑 4：`stack` / `queue` 用错方法**

- 现象：编译错误
- 原因：`stack` 只能 `top()`，`queue` 只能 `front()`
- 解决：记住 —— **栈看顶 `top`，队列看头 `front`**

**坑 5：迭代器失效**

- 现象：删除元素后程序崩溃
- 原因：`erase` 之后原来的迭代器可能失效
- 解决：用 `it = s.erase(it)` 接收返回值，或先记录再删

**坑 6：`priority_queue` 忘了清空**

- 现象：多组数据答案越来越大
- 原因：全局或复用的队列里还留着一组的数据
- 解决：每组数据前重新声明，或循环 `pop()` 到空

## 五、学习建议

按 5 小时推进（每学一个容器手敲一遍 + 找 1 道题）：

| 时段 | 容器 | 题目方向 | 验收标准 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | `vector` | 数组类 | 能开二维、能说清为什么不用定长数组 |
| 第 2 小时 | `stack` / `queue` | 括号匹配、BFS | 不会把 `top` 和 `front` 弄混 |
| 第 3 小时 | `priority_queue` | Top-K | 能写出小顶堆那行模板参数 |
| 第 4 小时 | `set` | 去重排序 | 能说清它和 `sort + unique` 的区别 |
| 第 5 小时 | `map` | 计数、映射 | 知道 `[]` 会插入，判存在用 `count` |

**每题验收动作**：

1. 说出**为什么选这个容器**，不选另一个（"因为方便"不算）
2. 说出这个容器的**单次操作复杂度**
3. 说出它的**一个坑**（越界？`[]` 插入？迭代器失效？）

> 容器选对了，代码量能少一半。选错了，光调 bug 就够写到考试结束。
