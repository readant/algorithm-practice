# 前缀和

> 前缀和是**预处理缓存**：把"每次都要重新累加"变成"提前算好，之后一次减法解决"。
> 代价是多开一个数组，回报是查询从 O(n) 降到 O(1)。

| 类型 | 预处理 | 单次查询 | 用来回答 |
| :-- | :-- | :-- | :-- |
| **一维求和** | O(n) | O(1) | 区间 [L,R] 的元素和 |
| **一维计数** | O(n) | O(1) | 区间 [L,R] 里满足条件的个数 |
| **二维求和** | O(n·m) | O(1) | 子矩阵的元素和 |

---

## 一、核心算法模型

### 1. 一维前缀和：为什么能变成减法

#### 1.1 核心思想

设 `S[i]` = 原数组**前 i 个**数的和（`S[0] = 0`）。

那么区间 `[L, R]` 的和，就是"前 R 个的和"减去"前 L-1 个的和"：

```
数组 a（下标 1~5）:  3    1    4    1    5
前缀和 S（S[0]=0）: 0    3    4    8    9   14
                    ↑    ↑    ↑    ↑    ↑    ↑
                   S[0] S[1] S[2] S[3] S[4] S[5]

求 a[2..4] 的和 = 1 + 4 + 1 = 6
用前缀和：S[4] − S[1] = 9 − 3 = 6   ✓
```

**为什么要减 `S[L-1]` 而不是 `S[L]`**：

`S[4]` 包含了 `a[1]~a[4]`，`S[1]` 是 `a[1]`。
`S[4] - S[1]` 剩下 `a[2]+a[3]+a[4]` —— **正好是 `a[2..4]`**。

如果写成 `S[4] - S[2] = 9 - 4 = 5`，那就把 `a[2]` 也减掉了，**少了左端点本身**。
这是最容易错的一处。

#### 1.2 为什么下标从 1 开始

这是前缀和最核心的技巧，两个好处：

**好处 1：不用特殊处理 L=1**

求 `[1, R]` 的和，公式是 `S[R] - S[0]`。因为 `S[0] = 0`，公式照样成立，代码不用加 if。

如果从 0 开始存，求 `[0, R]` 就要 `S[R] - S[-1]`，`-1` 越界了。

**好处 2：避免 `i-1` 为负**

构造时 `S[i] = S[i-1] + a[i]`，`i` 从 1 开始，最小就是 `S[0]`，**永远不会访问负下标**。

```cpp
int a[100005];              // 从 1 开始存
long long S[100005];        // S[0] = 0

// 构造
for (int i = 1; i <= n; i++) {
    S[i] = S[i - 1] + a[i];
}

// 查询 [L, R]
long long sum = S[R] - S[L - 1];
```

#### 1.3 例题拆解：连续子段和

**题意**：给一个长度为 n 的数组和 m 次询问，每次问 `[L, R]` 的和。

**暴力写法**：每次询问遍历一遍，O(n·m)。n=m=10⁵ 时是 10¹⁰，**必然超时**。

**前缀和写法**：预处理 O(n)，每次查询 O(1)，总计 O(n + m) = 2×10⁵，**轻松通过**。

```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int a[MAXN];
long long S[MAXN];

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) cin >> a[i];
    for (int i = 1; i <= n; i++) S[i] = S[i - 1] + a[i];

    while (m--) {
        int l, r;
        cin >> l >> r;
        cout << S[r] - S[l - 1] << "\n";
    }
    return 0;
}
```

> 注意 `S` 是 `long long`。n=10⁵、每个数 10⁹ 时，总和是 10¹⁴，**远超 int**。

### 2. 变体 A：前缀计数（不只用来求和）

**核心转换**：把"是否满足条件"变成 0/1 数组，再做前缀和。
这样 `S[R] - S[L-1]` 就是**区间内满足条件的个数**。

**例**：统计字符串 `[L, R]` 区间里有多少个字母 `a`。

```cpp
int cnt[100005];                    // 从 1 开始
for (int i = 1; i <= n; i++) {
    cnt[i] = cnt[i - 1] + (s[i] == 'a' ? 1 : 0);
}
// 区间 [L, R] 里 a 的个数
int num = cnt[R] - cnt[L - 1];
```

> 蓝桥真题「子串简写」就是这个套路：把"某个字符出现次数"做成前缀数组，
> 然后枚举分界点，用两次查询 O(1) 算出答案。

**推广**：任何"可减的统计量"都能这么做——偶数个数、大于 x 的个数、区间内的 1 的个数。

### 3. 变体 B：二维前缀和

求子矩阵的和，思路一样，只是容斥一下：

```
S[i][j] = S[i-1][j] + S[i][j-1] - S[i-1][j-1] + a[i][j]
          ↑上         ↑左         ↑左上被加了两次，减掉
```

求左上 `(x1,y1)` 到右下 `(x2,y2)` 的子矩阵和：

```cpp
long long sum = S[x2][y2]
              - S[x1 - 1][y2]
              - S[x2][y1 - 1]
              + S[x1 - 1][y1 - 1];
```

**记忆方法**：一维是两个端点，二维是**四个角**，加减号按"容斥"来：
`+ 右下 − 上 − 左 + 左上`。

### 4. 变体 C：什么不能用前缀和

**前缀积不行**（除法有精度问题、0 不能除）。

**"区间最大值"不行**（`max` 不可减：`max(a[1..5]) - max(a[1..2])` 得不到 `max(a[3..5])`）。

**判据**：这个运算**可不可逆**。加法可逆（减），乘法理论可逆（除，但会丢精度），
`max`/`min` 不可逆，**所以区间最值要用 STL 的 `max_element` 或者线段树**。

### 怎么选

1. **多次查询区间和** → 一维前缀和
2. **多次查询区间内满足条件的个数** → 前缀计数（0/1 转前缀和）
3. **多次查询子矩阵和** → 二维前缀和
4. **数组会被修改** → **前缀和失效**，改用差分（只改不查）或树状数组

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **下标从 1 开始** | `a[1..n]`，`S[0]=0` | 避免负下标，区间 `[1,R]` 公式通用 |
| **`long long` 存前缀和** | `long long S[]` | 累加极易超 `int`（21 亿） |
| **空间换时间** | 多开一个数组 | 查询从 O(n) 变 O(1) |
| **先想"能不能减"** | 判断运算可逆性 | 决定这题能不能用前缀和 |

```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
long long S[MAXN];          // 全局：自动清零，且能开大
```

## 三、初学者必踩的坑

**坑 1：区间和差一点点（L 和 L-1 搞混）**

- 现象：答案总是偏小或偏大，而且差值正好是 `a[L]`
- 原因：写成 `S[R] - S[L]`，把左端点本身也减掉了
- 解决：死记 `S[R] - S[L-1]`。**要减去的是左端点"之前"的所有和**

**坑 2：数组越界 / 输出负数**

- 现象：RE，或结果变成大负数
- 原因：下标从 0 开始存，`S[i-1]` 访问了 `S[-1]`；或者没开 `long long` 溢出
- 解决：下标统一从 1 开始；前缀和数组用 `long long`

**坑 3：数组被修改后还在用旧前缀和**

- 现象：改了 `a[i]` 之后查询结果不对
- 原因：**前缀和只适用于"只查不改"**。改一个元素，后面所有 `S[i]` 都失效
- 解决：要么每次重建（O(n)），要么改用树状数组

**坑 4：`S` 数组没多开**

- 现象：n=10⁵ 时 RE
- 原因：只开到 `MAXN`，但访问了 `S[MAXN]`
- 解决：一律 `MAXN + 5`

## 四、学习建议

按 5 小时推进：

| 时段 | 内容 | 验收标准 |
| :-- | :-- | :-- |
| 第 1 小时 | 一维前缀和模板 | 能闭卷写出构造 + 查询，能解释为什么减 `L-1` |
| 第 2 小时 | 连续子段和练习 | 能对比暴力与前缀和的复杂度差异 |
| 第 3 小时 | 前缀计数（统计字符） | 能把"统计个数"转成 0/1 数组再做前缀和 |
| 第 4 小时 | 二维前缀和 | 能默写容斥公式的四个角 |
| 第 5 小时 | 蓝桥真题：求和 / 子串简写 | 能独立分析出"这题该用前缀计数" |

**每题验收动作**：

1. 说出这题**查询多少次**、暴力会不会超时
2. 说出为什么 `S[R] - S[L-1]` 而不是 `S[R] - S[L]`
3. 说出这个数组**会不会被修改**（会改就不能用前缀和）

> 前缀和是蓝桥杯的常客。它最迷人的地方是把复杂计算变成了**一次减法**。
