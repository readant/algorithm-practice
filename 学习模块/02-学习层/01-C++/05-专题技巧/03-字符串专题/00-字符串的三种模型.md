# 字符串的三种模型

> 洛谷 [#104 入门5 字符串](https://www.luogu.com.cn/training/104) 共 15 题。
> 字符串题看着花样多，本质只有三个模型：**把字符当地址、把字符当数字、把字符串当可以被切开的东西**。

---

## 一、核心算法模型

### 1. 映射模型（哈希思想）：字符的"门牌号"

**核心思想**：ASCII 已经帮我们把字符变成了数字。26 个字母就是 26 个有序抽屉，每个字母有固定门牌号。

**实现技巧**：`s[i] - 'a'` 把 `'a'~'z'` 映射到 `0~25`，直接当数组下标。

**应用场景**：统计字母频次、去重、判断两个串字母组成是否相同（P1125 笨小猴、P1765 手机）。

```cpp
int cnt[26] = {0};
for (size_t i = 0; i < s.size(); i++) {
    if (s[i] >= 'a' && s[i] <= 'z') {
        cnt[s[i] - 'a']++;        // 字母对应的抽屉 +1
    }
}
```

> 规则不规则时直接**打表**比推公式可靠。P1765 的按键次数就是打表：
> `int key[26] = {1,2,3, 1,2,3, ..., 1,2,3,4};`

### 2. 偏移模型（转换思想）：字符的"变身术"

**核心思想**：字符底层是整数，加一个偏移量就变成另一个字符。大小写互换、加密位移都是这个。

**实现技巧**：小写 = 大写 + 32；**循环位移必须取模 `% 26`**，否则越过 `'z'` 就出界。

**应用场景**：大小写修正（P5733）、凯撒密码（P1914）、字母转数字（P1200）。

```cpp
// 往后移 n 位，超过 'z' 绕回 'a'
char encoded = (ch - 'a' + n) % 26 + 'a';

// 大写转小写
if (ch >= 'A' && ch <= 'Z') ch += 32;
```

> 手写 `+32` 可以，但更稳的是 `<cctype>` 的 `toupper` / `tolower`。
> 注意它们的形参是 `int`，安全写法：`(char)tolower((unsigned char)c)`。

### 3. 解析模型：文字"裁纸刀"

**核心思想**：要么像裁纸刀一样切出片段，要么像扫描仪一样找标记。

**实现技巧**：`find` 找位置、`substr` 切片段、`stringstream` 拆词。

**应用场景**：统计单词（P308）、读整句含空格（P5015）、插入翻转（P5734）、解析表达式（P1597）。

```cpp
size_t pos = s.find(target);
if (pos != string::npos) {                    // npos = 没找到
    string part = s.substr(pos, target.size());   // 从 pos 切出对应长度
}
```

### 怎么选

1. 要**按字符统计/去重** → 映射模型
2. 要**把字符换成另一个字符** → 偏移模型
3. 要**切片段、拆词、找子串** → 解析模型

## 二、必须掌握的"编程利器"

| 利器 | 怎么用 | 为什么重要 |
| :-- | :-- | :-- |
| **`std::string` 自带操作** | `+` 拼接、`==` 比较内容、`.size()` 取长度 | 不用手写字符数组和 `strlen` |
| **`getline(cin, s)`** | 读一整行，含空格 | `cin >>` 遇空格就停，句子题必须用它 |
| **`stringstream`** | 把一整串按空格自动拆成词 | 省去手写切分；但它会合并连续空格 |
| **`toupper` / `tolower`** | `<cctype>` 里 | 大小写转换不用手算 ±32 |

```cpp
#include <iostream>
#include <string>
#include <sstream>
using namespace std;

string s;
getline(cin, s);              // 读整行

stringstream ss(s);
string w;
while (ss >> w) {             // 每次取出一个词
    // 处理 w
}
```

## 三、初学者必踩的坑

**坑 1：消失的输入（缓冲区残留）**

- 现象：执行到 `getline` 直接跳过，不让你输入
- 原因：前面的 `cin >> n` 只拿走了数字，**把回车留在了缓冲区**，`getline` 一看有回车以为你输完了
- 解决：`getline` 之前先 `cin.ignore();`

**坑 2：下标越界（RE 元凶）**

- 现象：RE 或输出乱码
- 原因：长度为 10 的串，最大下标是 9，写成 `i <= s.length()` 就越界
- 解决：循环一律 `i < s.length()`

**坑 3：效率陷阱（TLE）**

- 现象：逻辑正确但超时
- 原因：`for (i = 0; i < s.length(); i++)` 每轮都重算一次长度
- 解决：`int len = s.size();` 先存起来，循环里用 `i < len`

**坑 4：`find` 循环不推进（死循环）**

- 现象：程序卡住不出结果
- 原因：`while ((pos = s.find(t)) != npos)` 每次都从 0 开始找，永远同一个位置
- 解决：`pos = s.find(t, pos + 1)`（允许重叠）或 `pos + t.size()`（不重叠）

## 四、学习建议

按 5 小时推进，一题一个模型：

| 时段 | 题目 | 练哪个模型 | 验收 |
| :-- | :-- | :-- | :-- |
| 第 1 小时 | P5733 自动修正 | 偏移（最简单） | 会判大小写并 ±32 |
| 第 2 小时 | P1914 凯撒密码 | 偏移（取模） | 能写出 `% 26` 并解释为什么 |
| 第 3 小时 | P5015 标准统计 | 解析（读整行） | 知道什么时候必须 `getline` |
| 第 4 小时 | P1765 手机 | 映射（打表） | 会写 26 个元素的查找表 |
| 第 5 小时 | P5734 文件处理软件 | 解析（插入/翻转） | 分得清 `find` / `substr` / `insert` |

> P1321 单词覆盖还原、P308 统计单词数是混合题（映射 + 解析），留作加练。
