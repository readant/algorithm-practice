# P1308 统计单词数

| 难度 | 标签 | 状态 | 语言 |
|------|------|------|------|
| 普及- | 字符串 / 模拟 / 大小写转换 | 已掌握 | C++ |

## 题目描述

### 问题描述

一般的文本编辑器都有查找单词的功能，该功能可以快速定位特定单词在文章中的位置，有的还能统计出特定单词在文章中出现的次数。

现在，请你编程实现这一功能，具体要求是：给定一个单词，请你输出它在给定的文章中出现的次数和第一次出现的位置。注意：匹配单词时，不区分大小写，但要求完全匹配，即给定单词必须与文章中的某一独立单词在不区分大小写的情况下完全相同（参见样例 1），如果给定单词仅是文章中某一单词的一部分则不算匹配（参见样例 2）。

### 输入格式

共 $2$ 行。  
第 $1$ 行为一个字符串，其中只含字母，表示给定单词；  
第 $2$ 行为一个字符串，其中只可能包含字母和空格，表示给定的文章。

### 输出格式

一行，如果在文章中找到给定单词则输出两个整数，两个整数之间用一个空格隔开，分别是单词在文章中出现的次数和第一次出现的位置（即在文章中第一次出现时，单词首字母在文章中的位置，位置从 $0$ 开始）；如果单词在文章中没有出现，则直接输出一个整数 $-1$。  
注意：空格占一个字母位。

### 数据范围

- $1 \le$ 第一行单词长度 $\le 10$  
- $1 \le$ 文章长度 $\le 10^6$

### 样例

#### 输入输出样例 #1

**输入 #1**

```
To
to be or not to be is a question
```

**输出 #1**

```
2 0
```

#### 输入输出样例 #2

**输入 #2**

```
to
Did the Ottoman Empire lose its power at that time
```

**输出 #2**

```
-1
```

## 解题思路

### 审题过程

- 给定两个字符串：一个单词（不含空格），一篇文章（包含字母和空格）。
- 需要在文章中找出**独立单词**（即被空格或文章边界包围的连续字母段）与给定单词匹配的次数。
- 匹配时不区分大小写，因此需要统一转换为小写（或大写）再比较。
- 位置从 0 开始，空格也算一个位置，因此某个单词的首字母位置就是它在原字符串中的下标。
- 如果给定单词只是文章中某个单词的一部分，不算匹配（例如 `to` 不能匹配 `Ottoman` 中的 `to`）。

### 主解法选择说明

本题采用**双指针扫描文章**作为主解法。文章长度可达 $10^6$，双指针一次遍历即可定位每个独立单词，时间复杂度 $O(n)$，且代码直观，适合初学者。虽然也可以使用 `stringstream` 按空格分割，但 `stringstream` 会忽略连续空格，导致位置计算复杂；而更高级的 KMP 算法在本场景下反而需要额外处理单词边界，代码繁琐。因此双指针法是最佳的教科书级实现。

### 主解法核心思路

1. 先将给定的单词转换为小写形式（因为匹配不区分大小写）。
2. 使用两个指针 `i` 和 `j` 遍历文章：
   - `i` 负责跳过空格，找到每个单词的起始位置；
   - `j` 从 `i` 开始向后移动，直到遇到空格或文章末尾，此时 `[i, j)` 区间正好是一个独立单词。
3. 检查该单词的长度是否与给定单词相同，如果相同，再逐字符比较（全部转为小写后比较）。
4. 如果完全一致，则计数器加 1；若这是第一次匹配，记录起始位置 `i`。
5. 将 `i` 移动到 `j` 之后，继续扫描下一个单词。

这种方法直接利用了文章中的空格作为单词分隔符，边界（文章开头和结尾）也自然处理，逻辑清晰。

### 其他解法思路

本题解法较为固定，以下主要介绍最优解（双指针扫描）。没有其他典型常见解法，因为 `stringstream` 处理位置不够准确，而 KMP 等字符串匹配算法会过度设计且对初学者不友好。

### 主解法伪代码设计

```
函数 转小写(字符串 s)：
    对于 s 中每个字符 ch：
        如果 ch 是大写字母，则 ch = ch - 'A' + 'a'
    返回 s

读入单词 word，文章 article
word = 转小写(word)
len = word的长度
计数 cnt = 0
第一次出现位置 firstPos = -1
i = 0
当 i < article长度 时：
    如果 article[i] 是空格：
        i = i + 1
        跳过
    否则：
        j = i
        当 j < article长度 且 article[j] 不是空格：
            j = j + 1
        // 此时 [i, j) 是一个单词
        如果 (j - i) == len：
            设置 匹配 = true
            对于 k = 0 到 len-1：
                如果 转小写(article[i+k]) != word[k]：
                    匹配 = false
                    跳出循环
            如果 匹配 为 true：
                cnt = cnt + 1
                如果 firstPos == -1：
                    firstPos = i
        i = j  // 继续从 j 开始扫描（j 当前是空格或文章末尾）
如果 cnt == 0：
    输出 -1
否则：
    输出 cnt 和 firstPos（空格隔开）
```

## 代码实现

### 主解法逐步讲解（带注释版本）

```cpp
#include <iostream>   // 提供 cin, cout 输入输出流
#include <string>     // 提供 string 类型和 getline 函数
#include <cctype>     // 提供 tolower 函数（用于字符转小写）

using namespace std;  // 使用标准命名空间，方便调用 cin/cout/string 等

// 将字符串转换为小写（不区分大小写的匹配前提）
string toLowerStr(string s) {
    for (char &c : s) {          // 范围 for 循环，c 是 s 中每个字符的引用
        c = tolower(c);          // tolower 来自 <cctype>，将大写转小写
    }
    return s;
}

int main() {
    // 输入输出加速，关闭 C 和 C++ 的输入输出同步，提高效率
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string word, article;
    cin >> word;                 // 读取给定单词（不含空格）
    cin.ignore();                // 忽略第一行末尾的换行符，为后面的 getline 做准备

    getline(cin, article);       // 读取整篇文章（可能包含空格）

    // 将给定单词转为小写，方便后续比较
    word = toLowerStr(word);
    int len = word.size();

    int cnt = 0;                 // 匹配次数
    int firstPos = -1;           // 第一次出现位置，初始 -1 表示未找到

    int i = 0;                   // 用于扫描文章的指针
    int n = article.size();

    while (i < n) {
        // 跳过所有空格，定位到下一个单词的起始
        while (i < n && article[i] == ' ') {
            ++i;
        }
        if (i >= n) break;       // 如果已经扫完，退出

        int j = i;               // j 从单词起始位置开始
        while (j < n && article[j] != ' ') {
            ++j;                 // 移动 j 直到遇到空格或末尾
        }

        // 现在 [i, j) 是一个完整的独立单词
        // 先判断长度是否相等，如果不等，不可能匹配
        if (j - i == len) {
            bool match = true;
            // 逐字符比较（都转为小写）
            for (int k = 0; k < len; ++k) {
                if (tolower(article[i + k]) != word[k]) {
                    match = false;
                    break;
                }
            }
            if (match) {
                ++cnt;
                if (firstPos == -1) {
                    firstPos = i;  // 第一次出现的位置就是当前单词起始下标
                }
            }
        }

        i = j;  // 继续从 j 位置扫描（j 现在是空格或末尾）
    }

    // 输出结果
    if (cnt == 0) {
        cout << -1 << '\n';      // 用 '\n' 而不是 endl，避免频繁刷新缓冲区
    } else {
        cout << cnt << ' ' << firstPos << '\n';
    }

    return 0;
}
```

#### 第1步：头文件逐个解释

- **`<iostream>`**：提供了 `cin`（标准输入）和 `cout`（标准输出）对象，以及 `ios::sync_with_stdio` 等输入输出流控制功能。
- **`<string>`**：提供了 `std::string` 类型，支持字符串的存储、操作，以及 `getline` 函数（用来读取包含空格的一整行）。
- **`<cctype>`**：提供了 `tolower` 函数，用于将字符转换为小写，是实现不区分大小写匹配的关键工具。

#### 第2步：`using namespace std;` 的作用与风险

`using namespace std;` 让我们可以直接写 `cin`、`cout`、`string` 而不需要加 `std::` 前缀。对初学者来说简洁方便。  
**风险**：在大型项目中可能导致命名冲突（例如自定义变量也叫 `cout`）。本题场景简单，使用是安全的。

#### 第3步：输入陷阱——`cin` 与 `getline` 混用

第一行单词用 `cin >> word` 读取，它会在读完后**留下换行符** `'\n'` 在输入缓冲区中。  
紧接着的 `getline(cin, article)` 会读取到那个换行符，以为是一行空内容，导致文章读取失败。  
**解决办法**：在两者之间插入 `cin.ignore();`，它会忽略（丢弃）缓冲区中的一个字符（即换行符），这样后续 `getline` 就能正确读取第二行内容。

#### 第4步：数据类型选择

- 单词和文章都存储在 `string` 中，因为长度可能很大（文章 $10^6$），`string` 自动管理内存，并在堆上分配空间，足以容纳。
- 计数 `cnt` 和位置 `firstPos` 使用 `int`，因为最大不超过文章长度 $10^6$，在 `int` 范围内（约 $2.1\times10^9$），所以无需 `long long`。
- 循环变量 `i`、`j`、`k` 用 `int` 也足够。

#### 第5步：性能优化

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

这两行用于关闭 C 和 C++ 标准输入输出的同步，并解除 `cin` 与 `cout` 的绑定，从而加快 `cin`/`cout` 的速度。在大量输入输出（如 $10^6$ 字符）时效果明显。  
注意：使用后不要再混用 `scanf`/`printf`，但本题全程使用 `cin`/`cout`，没有问题。

#### 第6步：输出换行

统一使用 `'\n'` 而不是 `endl`。`endl` 会额外执行 `flush` 操作，强制将缓冲区内容写入设备，这在大量输出时会降低性能。`'\n'` 只换行，不刷新缓冲区，效率更高。

### 解法对比总结

| 解法 | 时间复杂度 | 空间复杂度 | 代码复杂度 | 适用场景 |
| ------ | ------------ | ------------ | ------------ | ---------- |
| 双指针扫描（主解法） | $O(n)$，$n$ 为文章长度 | $O(1)$（不计输入存储） | 低，逻辑直观 | 通用的单词匹配，适合初学者 |
| `stringstream` 分割（不推荐） | $O(n)$ | $O(n)$（额外复制） | 中等，需额外处理位置 | 仅在单词间隔单一空格且不需要位置时可用 |
| KMP 字符串匹配（过度设计） | $O(n+m)$ | $O(m)$ | 高，需修改模式串处理边界 | 大规模重复匹配或特定模式串时可用 |

**推荐建议**：  

- 初学者应掌握主解法（双指针），因为它直接操作原字符串，位置计算准确，且代码清晰易改。  
- 竞赛中直接使用主解法即可，时间复杂度已是线性，足够通过 $10^6$ 的数据。

## 易错点

- **大小写转换不彻底**：只转换了给定单词，但比较时忘记转换文章中的字符，导致匹配失败。正确做法是统一转换为小写（或大写）后再比较。
- **未处理单词边界**：仅用 `find` 函数查找子串会错误匹配到其他单词内部（如样例 2）。必须确保匹配的片段是被空格或字符串首尾包围的独立单词。
- **位置计算错误**：文章中的位置从 0 开始，空格也算一个位置。记录 `firstPos` 时必须在匹配成功的单词起始下标 `i` 处，而不是匹配到的字符偏移。
- **`cin.ignore()` 遗忘**：如果在 `cin >> word` 后直接 `getline`，会导致文章读为空。务必在中间添加 `cin.ignore();` 忽略换行符。
- **文章开头或结尾有空格**：双指针的跳过逻辑要正确处理，避免访问越界。我们在外层 `while` 中先跳过空格，再检查 `i >= n`，可以安全处理所有情况。
- **输出格式错误**：如果未找到，只输出 `-1`，不要额外输出空格或换行符；如果找到，两个整数之间用一个空格隔开，行末换行。

## 总结发散

### 核心模式

双指针逐词扫描 + 大小写归一化比较，模拟文本编辑器中的单词查找功能。

### 延伸/推导

本题本质是**单词边界识别**问题，其核心在于用空格作为分隔符。如果文章中的分隔符更复杂（如标点符号、换行），只需将跳过条件扩展为“非字母”即可。此外，若要统计多个单词的出现次数，可构建字典（`unordered_map`）并分别扫描，但此时需注意位置记录方式。扩展到大写转换时，`tolower` 仅对英文字母有效，若处理其他语言则需考虑 Unicode 等编码方案，但竞赛题目通常局限于 ASCII 字母。
