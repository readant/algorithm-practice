## 题目描述

### 问题描述

小果有一个只有两个键的键盘。一天，她打出了一个只有这两个字符的字符串。当这个字符串里含有 `VK` 这个字符串的时候，小果就特别喜欢这个字符串。所以，她想改变至多一个字符（或者不做任何改变）来最大化这个字符串内 `VK` 出现的次数。给出原来的字符串，请计算她最多能使这个字符串内出现多少次 `VK`（只有当 `V` 和 `K` 正好相邻时，我们认为出现了 `VK`。）

### 输入格式

第一行给出一个数字 $n$，代表字符串的长度。  
第二行给出一个字符串 $s$。

### 输出格式

第一行输出一个整数代表所求答案。

### 数据范围

对于 $100\%$ 的数据，$1 \le n \le 100$。

### 样例

#### 输入 #1

```
2
VK
```

#### 输出 #1

```
1
```

#### 输入 #2

```
2
VV
```

#### 输出 #2

```
1
```

#### 输入 #3

```
1
V
```

#### 输出 #3

```
0
```

#### 输入 #4

```
20
VKKKKKKKKKVVVVVVVVVK
```

#### 输出 #4

```
3
```

#### 输入 #5

```
4
KVKV
```

#### 输出 #5

```
1
```

## 解题思路

### 审题过程

- 给定一个长度为 $n$ 的字符串，只包含 `'V'` 和 `'K'` 两种字符。
- 我们可以**至多改变一个字符**（也可以不改），也就是把某个位置的字符改成另一个字符。
- 目标：使得改动后的字符串中，**相邻且恰好为 `"VK"` 的子串出现次数最多**。
- 注意：`"VK"` 必须连续出现，且字符顺序不能颠倒。

### 主解法选择说明

本题 $n$ 最大只有 $100$，数据规模非常小，因此**最直接、最不容易出错的解法就是暴力枚举**：分别尝试“不修改”以及“修改每一个位置（改写成另一个字符）”，对每种情况重新统计 `"VK"` 出现的次数，取最大值。  
这种解法虽然时间复杂度为 $O(n^2)$，但 $n=100$ 时完全够用，而且**逻辑清晰、对初学者非常友好**，所以将其作为主讲解对象。

### 主解法核心思路

我们把“统计一个字符串中有多少个 `"VK"`”封装成一个独立的函数 `countVK`。然后：

1. 先计算原字符串的 `"VK"` 个数，作为备选答案。
2. 枚举每一个位置 $i$（从 $0$ 到 $n-1$）：
   - 把 `s[i]` 临时改成另一个字符（`'V'` 变成 `'K'`，`'K'` 变成 `'V'`）。
   - 调用 `countVK` 统计修改后的字符串，更新答案。
   - 把 `s[i]` 恢复原状，以便尝试下一个位置。

最后输出答案即可。  
这种做法的优点是不需要担心“修改是否会破坏原有 `"VK"`”等复杂情况，因为每次修改后我们都**重新完整统计**，结果一定是正确的。

### 其他解法思路

本题还存在 **$O(n)$ 贪心解法**，适合对算法效率有更高要求的场景：

- **贪心法**：先统计所有原串中的 `"VK"` 并用标记数组记录这些字符已被使用，然后寻找是否存在相邻的、两个字符均未被标记过的 `"VV"` 或 `"KK"`，如果存在则可以通过修改一个字符新增一个 `"VK"`，答案加 1。  
  该解法需要仔细处理标记，避免破坏已有的 `"VK"`，实现起来稍复杂，但效率更高。

### 主解法伪代码设计

```
函数 countVK(s):
    cnt = 0
    循环 i 从 0 到 s.length - 2:
        如果 s[i] == 'V' 且 s[i+1] == 'K':
            cnt = cnt + 1
    返回 cnt

主程序:
    读入 n, s
    ans = countVK(s)          // 不修改的情况
    循环 i 从 0 到 n - 1:
        original = s[i]
        如果 original == 'V':
            s[i] = 'K'
        否则:
            s[i] = 'V'
        ans = max(ans, countVK(s))
        s[i] = original       // 恢复
    输出 ans
```

## 代码实现

### 主解法逐步讲解（带注释版本）

```cpp
// 头文件 iostream：提供 cin、cout 等标准输入输出流
#include <iostream>
// 头文件 string：提供 string 类型，用于存储和操作字符串
#include <string>
using namespace std;

// 统计字符串 s 中 "VK" 出现的次数
// 参数用 const string& 表示引用传递，避免拷贝整个字符串（提高效率），同时 const 保证不会修改原字符串
int countVK(const string& s) {
    int cnt = 0;                         // 计数器
    // 遍历到倒数第二个字符，因为需要检查 s[i] 和 s[i+1]
    for (size_t i = 0; i + 1 < s.size(); ++i) {
        if (s[i] == 'V' && s[i + 1] == 'K') {
            ++cnt;
        }
    }
    return cnt;
}

int main() {
    // 关闭 C 和 C++ 的输入输出同步，加快 cin/cout 速度
    ios::sync_with_stdio(false);
    // 解除 cin 和 cout 的绑定，进一步提速
    cin.tie(nullptr);

    int n;
    string s;
    cin >> n >> s;    // 读取长度和字符串

    // 记录答案，初始为不修改时的 "VK" 数量
    int ans = countVK(s);

    // 枚举每一个位置，尝试修改该位置的字符
    for (int i = 0; i < n; ++i) {
        char original = s[i];   // 备份原字符，用于恢复

        // 将 s[i] 改为另一个字符
        if (original == 'V') {
            s[i] = 'K';
        } else {  // original == 'K'
            s[i] = 'V';
        }

        // 修改后统计，并与当前答案比较，保留较大值
        int cur = countVK(s);
        if (cur > ans) ans = cur;

        // 恢复原字符，保证下一次枚举从原始字符串开始
        s[i] = original;
    }

    // 输出最终答案，用 '\n' 换行，不用 endl（endl 会强制刷新缓冲区，影响性能）
    cout << ans << '\n';
    return 0;
}
```

**逐步详细解释：**

1. **头文件选择**  
   - `<iostream>`：提供了 `cin`、`cout` 这些最基本输入输出工具，就像工具箱里的扳手和螺丝刀，几乎所有 C++ 程序都少不了它。  
   - `<string>`：提供了 `string` 类型，让我们可以方便地存储和操作字符串（如 `s[i]` 访问字符、`s.size()` 获取长度），比 C 风格的字符数组更安全、更易用。

2. **`using namespace std;` 的作用**  
   标准库中的名字（如 `cin`、`cout`、`string`）都定义在命名空间 `std` 中。写上这句话后，我们就不用每次都写 `std::cin`、`std::string` 了。  
   **风险提示**：在大型项目中，`using namespace std;` 可能导致命名冲突（比如自定义了名为 `cout` 的变量），但竞赛题目中通常安全，且能简化代码，适合初学者。

3. **`countVK` 函数的设计**  
   我们把“统计 `"VK"`”单独做成函数，使主逻辑更清晰。  
   - 参数使用 `const string&`：`&` 表示**引用传递**，函数内部直接使用原字符串的内存，不会产生拷贝，节省时间和空间。加上 `const` 则保证函数内部不会意外修改字符串，这是一种良好的编程习惯。  
   - 遍历时用 `size_t i = 0; i + 1 < s.size(); ++i`，因为 `s.size()` 返回的是无符号整数 `size_t`，用 `i < s.size() - 1` 可能发生下溢（当 `s.size()` 为 0 时），而题目保证 $n \ge 1$，但写成 `i + 1 < s.size()` 更安全，避免边界问题。

4. **主函数中的输入输出优化**  
   - `ios::sync_with_stdio(false);`：默认情况下 C++ 的 `cin/cout` 会与 C 的 `stdio` 同步，这会降低效率。关闭同步后，`cin/cout` 速度会提升，适合输入输出量较大的题目。  
   - `cin.tie(nullptr);`：`cin` 默认在每次输入前会先刷新 `cout` 的缓冲区，这种绑定也会拖慢速度。解绑后，我们可以在需要时手动刷新，提升效率。  
   - 由于题目是纯数字和字符串输入，不含空格，因此**不存在 `cin` 和 `getline` 混用的问题**，不需要使用 `cin.ignore()`。

5. **枚举修改位置的逻辑**  
   - 每次备份 `original`，修改 `s[i]` 后调用 `countVK`，然后立即恢复。这样保证每次尝试都是基于原字符串的**单点修改**，符合题目“至多改变一个字符”的要求。  
   - 答案 `ans` 的初值设为原串的统计结果，这样“不修改”的情况也被覆盖了。

6. **输出换行**  
   使用 `'\n'` 而非 `endl`，因为 `endl` 除了换行还会调用 `flush` 强制刷新输出缓冲区，这在大量输出时会造成性能损失。本题输出仅一行，区别不大，但养成用 `'\n'` 的好习惯。

### 其他解法实现（贪心法）

**思路说明**  
贪心法需要先找出原串中所有的 `"VK"`，并用一个标记数组记录这些位置已被“占用”。因为一个字符只能属于一个 `"VK"`（不能同时和左边、右边分别组成两个），所以我们标记后，再扫描一遍字符串，寻找是否存在两个相邻且都未标记的字符，它们恰好是 `"VV"` 或 `"KK"`。  
如果存在，则可以通过修改其中一个字符制造出一个新的 `"VK"`，且不会破坏已有的 `"VK"`（因为被修改的字符未被标记）。答案就在原 `"VK"` 个数上加 1。否则答案就是原个数。

**完整代码**

```cpp
#include <iostream>
#include <string>
#include <vector>   // 提供 vector 容器，用来做标记数组
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    string s;
    cin >> n >> s;

    // 标记数组，used[i] = 1 表示 s[i] 已经被某个原有的 "VK" 使用了
    // 使用 vector<char> 而不是 vector<bool> 原因：vector<bool> 是特化版，
    // 其 operator[] 返回的不是真正的 bool 引用，容易引发预期外的错误，
    // 而 vector<char> 行为与普通数组完全一致，更安全直观。
    vector<char> used(n, 0);

    int ans = 0;
    // 第一遍扫描：统计原有的 "VK" 并标记
    for (int i = 0; i + 1 < n; ++i) {
        if (!used[i] && !used[i + 1] && s[i] == 'V' && s[i + 1] == 'K') {
            ++ans;
            used[i] = used[i + 1] = 1;   // 这两个字符被占用
        }
    }

    // 第二遍扫描：查找是否存在未被占用的相邻 "VV" 或 "KK"
    bool canAdd = false;
    for (int i = 0; i + 1 < n; ++i) {
        if (!used[i] && !used[i + 1]) {
            if ((s[i] == 'V' && s[i + 1] == 'V') ||
                (s[i] == 'K' && s[i + 1] == 'K')) {
                canAdd = true;
                break;
            }
        }
    }

    if (canAdd) ++ans;
    cout << ans << '\n';
    return 0;
}
```

**复杂度分析**  

- 时间复杂度：$O(n)$，只需扫描两遍字符串。  
- 空间复杂度：$O(n)$，用于标记数组。

### 解法对比总结

| 解法       | 时间复杂度 | 空间复杂度 | 代码复杂度 | 适用场景                     |
| ---------- | ---------- | ---------- | ---------- | ---------------------------- |
| 暴力枚举   | $O(n^2)$   | $O(1)$     | 简单       | 小数据（$n \le 100$），教学 |
| 贪心法     | $O(n)$     | $O(n)$     | 中等       | 大数据，竞赛实战             |

- **初学者建议掌握主解法（暴力枚举）**，因为它逻辑直白，不易出错，而且 $n$ 小的时候完全够用，能帮助巩固“枚举”和“函数封装”的思想。
- **进阶学习者可了解贪心法**，它虽然需要小心处理标记，但能让你体会如何从 $O(n^2)$ 优化到 $O(n)$，是算法优化的入门范例。
- **竞赛中若 $n$ 较大（例如 $10^5$），建议使用贪心法**，因为时间效率更高，但务必注意标记数组的正确性。

## 易错点

- **修改后忘记恢复原字符**  
  在枚举每个位置时，如果修改了 `s[i]` 但没有在下次循环前恢复，会导致后续枚举基于错误的状态。正确做法：每次备份原始字符，统计后立即恢复。

- **统计 `"VK"` 时的边界越界**  
  循环条件写成 `i < s.size() - 1`，当 `s.size()` 为 0 时（本题不会，但考虑通用性）会出错。建议写成 `i + 1 < s.size()`，更安全。

- **贪心法中标记数组与修改的冲突**  
  如果标记不完整或使用 `vector<bool>` 导致引用问题，可能会漏判或误判。使用 `vector<char>` 可避免这个陷阱。

- **输出格式错误**  
  题目要求输出一行一个整数，不要输出多余空格或换行。我们的代码只输出 `ans` 和一个换行，符合要求。

- **未考虑“不做任何改变”**  
  暴力解法中 `ans` 初始化为原串结果，贪心法中原 `ans` 已经统计原串，所以都已覆盖。若忘记初始化，可能漏掉不修改的情况。

## 总结发散

### 核心模式

“单点修改 + 重新统计”的枚举思想：当数据范围很小时，暴力尝试所有可能的修改，用封装好的统计函数计算每种情况的结果。

### 延伸/推导

本题的暴力枚举其实是“模拟所有修改方案”，而贪心法则是基于“最多增加一个 `"VK"`”的性质进行优化。  
更一般地，如果允许修改 $k$ 个字符，或者字符串长度变大，就需要动态规划或更复杂的搜索策略。  
从埃氏筛到欧拉筛的优化思路类似：先用简单方法保证正确，再逐步挖掘性质来降低复杂度——这是算法学习中非常重要的递进过程。
