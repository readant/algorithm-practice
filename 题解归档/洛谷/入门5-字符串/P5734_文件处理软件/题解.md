## 题目描述

### 问题描述

你需要开发一款文字处理软件。最开始时输入一个字符串作为初始文档。可以认为文档开头是第 $0$ 个字符。需要支持以下操作：

- `1 str`：后接插入，在文档后面插入字符串 `str`，并输出文档的字符串；
- `2 a b`：截取文档部分，只保留文档中从第 $a$ 个字符起 $b$ 个字符，并输出文档的字符串；
- `3 a str`：插入片段，在文档中第 $a$ 个字符前面插入字符串 `str`，并输出文档的字符串；
- `4 str`：查找子串，查找字符串 `str` 在文档中最先的位置并输出；如果找不到输出 `-1`。

为了简化问题，规定初始的文档和每次操作中的 `str` 都不含有空格或换行。最多会有 $q$ 次操作。

### 输入格式

第一行输入一个正整数 $q$，表示操作次数。

第二行输入一个字符串 `str`，表示最开始的字符串。

第三行开始，往下 $q$ 行，每行表示一个操作，操作如题目描述所示。

### 输出格式

一共输出 $q$ 行。

对于每个操作 $1,2,3$，根据操作的要求输出一个字符串。

对于操作 $4$，根据操作的要求输出一个整数。

### 输入输出样例 #1

#### 输入 #1

```
4
ILove
1 Luogu
2 5 5
3 3 guGugu
4 gu
```

#### 输出 #1

```
ILoveLuogu
Luogu
LuoguGugugu
3
```

### 数据范围

数据保证，$1 \leq q \leq 100$，开始的字符串长度 $\leq 100$。

## 解题思路

### 审题过程

- 我们需要维护一个初始文档字符串。
- 共有四种操作，每种操作都对应字符串的一种基本修改或查询。
- 操作指令的第一位是数字（1~4），后面的参数个数和类型各不相同。
- 题目保证了参数（包括 `str`）不含空格，所以可以直接用 `cin >>` 读取。
- 每次操作完成后，对于 1、2、3 号操作要输出修改后的完整文档；对于 4 号操作输出查找结果（位置或 -1）。

### 主解法选择说明

本题是典型的字符串模拟题，**教科书级解法就是直接使用 C++ 标准库的 `string` 类型**。`string` 提供了 `append()`、`substr()`、`insert()`、`find()` 等现成成员函数，能够完美对应四种操作，代码简洁、不易出错，非常适合初学者建立“字符串作为对象”的编程思维。因此我们把它作为主解法详细讲解。

### 主解法核心思路

我们使用一个 `string doc` 存储当前文档，然后依次处理 $q$ 条指令：

- **操作1**：调用 `doc.append(str)` 将 `str` 追加到文档末尾。
- **操作2**：先利用 `doc.substr(a, b)` 截取从第 `a` 个字符开始的 `b` 个字符，**注意**：`substr(pos, len)` 的第一个参数是起始位置，第二个参数是长度，然后将截取结果重新赋值给 `doc`。
- **操作3**：调用 `doc.insert(a, str)` 在位置 `a` 之前插入 `str`（文档索引从 0 开始）。
- **操作4**：调用 `doc.find(str)` 查找子串首次出现的位置，如果返回值等于 `string::npos` 则输出 `-1`，否则输出该位置。

每次操作后，1~3 号操作直接输出 `doc` 即可。

### 其他解法思路

本题解法较为固定，以下主要介绍最优解（即 `string` 成员函数法）。  
若不允许使用 STL，也可以使用字符数组手动模拟：维护一个字符数组和当前长度，每次插入/删除时移动后续字符，代码会更长且容易出错，一般不推荐。

### 主解法伪代码设计

```
输入 q
输入 doc

循环 i = 1 到 q：
    输入 op
    如果 op == 1：
        输入 str
        doc = doc + str          // 或 append(str)
        输出 doc
    否则如果 op == 2：
        输入 a, b
        doc = doc.substr(a, b)   // 截取并替换原文档
        输出 doc
    否则如果 op == 3：
        输入 a, str
        doc.insert(a, str)       // 在 a 位置前插入
        输出 doc
    否则如果 op == 4：
        输入 str
        pos = doc.find(str)
        如果 pos == 不存在：
            输出 -1
        否则：
            输出 pos
```

## 代码实现

### 主解法逐步讲解（带注释版本）

```cpp
#include <iostream>   // 提供 cin、cout 等标准输入输出流
#include <string>     // 提供 string 类型及其成员函数

using namespace std;  // 使用标准命名空间，方便直接使用 cout、string 等

int main() {
    // 关闭 C 与 C++ 的输入输出同步，加快 cin/cout 速度
    ios::sync_with_stdio(false);
    cin.tie(nullptr); // 解除 cin 与 cout 的绑定，进一步提速

    int q;
    cin >> q;         // 读取操作次数

    string doc;
    cin >> doc;       // 读取初始文档（无空格）

    while (q--) {     // 循环 q 次
        int op;
        cin >> op;    // 读取操作类型

        if (op == 1) {
            string str;
            cin >> str;              // 读取要追加的字符串
            doc.append(str);         // 将 str 追加到 doc 末尾
            cout << doc << '\n';     // 输出结果，用 '\n' 换行
        }
        else if (op == 2) {
            int a, b;
            cin >> a >> b;           // 读取起始位置和长度
            doc = doc.substr(a, b);  // 截取从 a 开始的 b 个字符，替换原文档
            cout << doc << '\n';
        }
        else if (op == 3) {
            int a;
            string str;
            cin >> a >> str;         // 读取插入位置和插入字符串
            doc.insert(a, str);      // 在 doc 的第 a 个字符前插入 str
            cout << doc << '\n';
        }
        else if (op == 4) {
            string str;
            cin >> str;              // 读取要查找的子串
            size_t pos = doc.find(str); // 查找首次出现位置，返回 size_t 类型
            if (pos == string::npos) {  // string::npos 是 size_t 的最大值，表示未找到
                cout << -1 << '\n';
            } else {
                cout << pos << '\n';    // 位置从 0 开始，符合题目要求
            }
        }
    }

    return 0;
}
```

**逐步讲解（为什么这样写）**：

1. **头文件的选择**：  
   - `<iostream>`：提供 `cin`、`cout` 等输入输出对象，是几乎所有 C++ 程序都需要的“工具箱”。  
   - `<string>`：提供 `string` 类型以及它的成员函数，比如 `append`、`substr`、`insert`、`find`。如果不包含这个头文件，编译器就不认识 `string`。  
   > 通俗来说：你要用“字符串”这个工具，就必须先把装着它的工具箱 `<string>` 打开。

2. **`using namespace std;`**：  
   标准库中的所有类型和函数都定义在 `std` 命名空间中。加上这一句后，我们可以直接写 `string`、`cout`，而不必写成 `std::string`、`std::cout`。  
   在小型程序（如竞赛题）中使用很便捷，但要注意它可能引起命名冲突（即“命名空间污染”），在大型项目中一般不推荐。

3. **输入输出加速**：  
   `ios::sync_with_stdio(false);` 和 `cin.tie(nullptr);` 是竞赛中常用的优化写法。  
   - 默认情况下，C++ 的 `cin/cout` 会与 C 的 `scanf/printf` 保持同步，这带来了额外开销。关闭同步后，`cin/cout` 速度会提升。  
   - `cin.tie(nullptr)` 解除 `cin` 与 `cout` 的绑定，避免每次 `cin` 之前都刷新 `cout` 缓冲区，进一步提高效率。  
   本题数据量不大，不加也能通过，但加上是好习惯。

4. **`doc.append(str)` 与 `doc = doc + str`**：  
   `append` 是 `string` 的成员函数，作用是在原字符串末尾添加新内容。用 `doc += str` 或 `doc = doc + str` 也可以达到同样效果。这里选择 `append` 是为了让代码意图更明确（“追加”）。

5. **`doc.substr(a, b)`**：  
   该函数返回从位置 `a` 开始、长度为 `b` 的子串。注意：它不会修改原字符串，所以我们需要将结果**重新赋值**给 `doc`，才能实现“截取保留”的效果。

6. **`doc.insert(a, str)`**：  
   在位置 `a`（第 `a` 个字符）**之前**插入 `str`。文档索引从 0 开始，所以插入到开头用 `0`，插入到末尾用 `doc.length()`。

7. **查找子串 `doc.find(str)`**：  
   `find` 返回类型是 `size_t`（无符号整数）。如果找不到，返回 `string::npos`（这是一个静态常量，等于 `size_t` 的最大值）。直接判断 `pos == string::npos` 是最安全的做法，不要用 `pos == -1`，因为 `size_t` 是无符号的，与 `-1` 比较可能产生意外结果。

8. **为什么输出用 `'\n'` 而不是 `endl`**：  
   `endl` 除了换行外还会**强制刷新输出缓冲区**，频繁刷新会降低程序性能。在绝大多数算法题中，使用 `'\n'` 就足够了。只有交互式题目才需要立即刷新输出。

- 竞赛中直接使用 `string` 即可，STL 在大部分 OJ 上都支持，性能也足够。

## 易错点

- **索引从 0 开始**：题目明确指出文档开头是第 0 个字符，因此 `substr(a, b)` 中的 `a` 和 `insert(a, str)` 中的 `a` 都直接使用输入值，无需加减。  
- **`substr` 截取后一定要重新赋值**：`substr` 不会修改原字符串，如果忘记重新赋值，文档不会被截断，导致错误。  
- **`find` 的返回值判断**：`string::find` 返回 `size_t` 类型，不能用 `== -1` 判断，必须用 `== string::npos`，否则在某些编译器下会警告或行为异常。  
- **头文件缺失**：使用 `string` 必须包含 `<string>`，否则编译报错。很多初学者以为 `<iostream>` 已经包含了它，其实不然。  
- **无空格输入参数**：题目保证 `str` 不含空格，所以用 `cin >>` 读取没问题；如果题目改成含空格的字符串，就需要改用 `getline`，并且要注意与 `cin` 混用时的缓冲区残留问题（本题不需要）。

## 总结发散

### 核心模式

字符串操作 + 模拟指令。

### 延伸/推导

`string` 的 `find` 函数采用高效的字符串匹配算法（通常是朴素匹配或优化过的 Boyer-Moore-Horspool），但对于本题数据量（$q\le 100$，文档长度最多也仅为操作后累积长度，不超过 $100 + 100\times 100 = 10100$ 字符），直接使用即可。  
如果你未来遇到大规模文本匹配问题，可以进一步学习 KMP 算法，它能将查找复杂度从 O(n*m) 降低到 O(n+m)，但本题用不到。
