## 题目描述

### 问题描述

给定一串长度不超过 255 的 PASCAL 语言代码，只包含 `a,b,c` 三个变量，且只有赋值语句。每条赋值语句的格式为 `[变量]:=[变量或一位整数];`。所有变量初始值为 0，请按顺序执行所有赋值语句，最终输出 `a b c` 的值（用空格隔开）。

### 输入格式

一行字符串，为合法的 PASCAL 赋值语句序列（不含空格），长度不超过 255。

### 输出格式

一行，三个整数，分别表示变量 `a`、`b`、`c` 的最终值，中间用空格隔开。

### 数据范围

字符串长度不超过 255。

### 样例

#### 输入 #1

```
a:=3;b:=4;c:=5;
```

#### 输出 #1

```
3 4 5
```

## 解题思路

### 审题过程

- 输入是一整串连续的赋值语句，每条以分号 `;` 结尾，语句之间没有空格。
- 只涉及三个变量 `a`、`b`、`c`，初始值均为 0。
- 等号右边的值可能是一位数字（`'0'` ~ `'9'`），也可能是另一个变量（`'a'`、`'b'`、`'c'`）。
- 需要按顺序逐条执行，右边的变量引用的是该变量**当前**的值。
- 最后按 `a b c` 的顺序输出三个整数。

### 主解法选择说明

本题是典型的**字符串模拟**题，代码短、逻辑直白，最适合作为初学者的“模拟与解析”入门练习。由于数据规模极小（长度 ≤ 255），无需任何复杂算法，直接扫描字符串并模拟变量赋值即可。

### 主解法核心思路

我们可以把整个字符串看成一个字符数组，用下标 `i` 从左到右扫描。每次遇到形如 `变量:=值;` 的模式时，就解析出三个关键信息：

- **左变量**：`s[i]`，即赋值号左边的字母。
- **右值**：`s[i+3]`，即赋值号右边的字符（因为 `:=` 占两个字符，所以右值在 `i+3` 位置）。
- 然后根据右值类型更新对应变量的值：
  - 若右值是数字字符（`'0'` ~ `'9'`），则直接赋值为该数字。
  - 若右值是变量字母（`'a'`、`'b'`、`'c'`），则赋值为该变量当前的值。

每条语句结束后，指针移到分号后的下一个字符，继续处理下一条。

### 其他解法思路

本题解法较为固定，以下主要介绍上述直接模拟法。没有其他典型解法变种。

### 主解法伪代码设计

```
读入字符串 s
设数组 var['a'..'c'] = {0, 0, 0}
i = 0
while i < s.length():
    左变量 = s[i]          // 字母
    // 跳过 ":="，i 移到右值位置
    i = i + 3
    右值字符 = s[i]
    if 右值字符是数字 '0'..'9':
        var[左变量] = 右值字符 - '0'
    else:
        var[左变量] = var[右值字符]
    // 跳过分号
    i = i + 2              // 因为右值占1位，分号占1位
输出 var['a'], var['b'], var['c']
```

## 代码实现

### 主解法逐步讲解（带注释版本）

```cpp
#include <iostream>   // cin, cout
#include <string>     // string 类型

using namespace std;  // 使用标准命名空间，方便直接使用 cin/cout/string

int main() {
    // 用 ios::sync_with_stdio(false); 关闭 C 和 C++ 流同步，提高 cin/cout 速度
    // 用 cin.tie(nullptr); 解除 cin 和 cout 的绑定，进一步提速
    // 对本题输入量极小，非必须，但养成良好习惯。
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s;           // 存储输入的 PASCAL 代码串
    cin >> s;           // 直接读取整串，无空格，故无需 getline

    // 用 int 数组存储三个变量的值，下标用字符 'a'、'b'、'c' 直接映射
    // 因为字符在内存中对应 ASCII 码，'a' 的值是 97，所以数组大小设为 128 足够容纳 'c'
    int var[128] = {0}; // 全部初始化为 0，这样未赋值的变量就是 0

    int i = 0;          // 当前扫描位置
    int len = s.length();

    while (i < len) {
        // 1. 取出左变量字符
        char left = s[i];

        // 2. 指针跳过 ":="，即从当前位置往后移动 3 个字符
        //    注意：s[i] 是左变量，s[i+1] 是 ':'，s[i+2] 是 '='，s[i+3] 才是右值
        i = i + 3;

        // 3. 读取右值字符
        char right = s[i];

        // 4. 判断右值是数字还是变量
        if (right >= '0' && right <= '9') {
            // 数字字符转整数：字符 '0' 的 ASCII 码是 48，减去 '0' 得到数值
            var[left] = right - '0';
        } else {
            // 右值是变量，将当前该变量的值赋给 left 变量
            var[left] = var[right];
        }

        // 5. 跳过右值字符和分号，指向下一条语句的开头
        //    右值占 1 位，分号占 1 位，所以 i 向后移动 2
        i = i + 2;
    }

    // 输出结果，用空格隔开，最后换行用 '\n'
    // 注意：不要用 endl，因为它会强制刷新缓冲区，影响性能。
    cout << var['a'] << ' ' << var['b'] << ' ' << var['c'] << '\n';

    return 0;
}
```

**代码分步解释：**

1. **头文件选择**：  
   - `<iostream>` 提供了 `cin` 和 `cout`，负责输入输出。  
   - `<string>` 提供了 `string` 类型，方便存储和操作字符串。  
   - `using namespace std;` 允许我们直接写 `cin`、`cout` 和 `string`，而不用在前面加 `std::`。虽然存在命名空间污染风险，但本题规模极小，完全可接受，并且是竞赛中最常见的写法。

2. **变量存储设计**：  
   - 使用 `int var[128]`，用字符的 ASCII 码作为下标，例如 `var['a']` 就是变量 `a` 的值。数组大小 128 足够容纳 `'a'`、`'b'`、`'c'` 以及数字字符，简单且高效。  
   - 数组在栈上分配，大小固定，但因为只要 128 个 int（约 512 字节），完全安全。  
   - 初始化为 `{0}`，所有变量默认为 0，符合题目“未赋值变量值为 0”的要求。

3. **扫描逻辑**：  
   - `i` 指向当前待处理语句的第一个字符（即左变量）。  
   - 已知格式固定为 `变量:=值;`，因此右值一定在 `i+3` 位置。  
   - 解析右值后，更新 `var[left]`。  
   - 跳过分号时，`i` 移动 2 位（右值占 1 位，分号占 1 位），恰好指向下一条语句的左变量（因为格式紧凑，无空格）。  
   - 循环直到处理完整个字符串。

4. **输入陷阱提醒**：  
   - 本题输入只包含一行无空格的字符串，使用 `cin >> s` 即可安全读取，不会遇到 `getline` 与 `cin` 混用的缓冲区问题。因此代码中**不需要** `cin.ignore()`。  
   - 若题目描述允许包含空格，则必须改用 `getline(cin, s)`，并注意混用时的处理，但本题明确无空格，所以简单处理即可。

5. **性能优化**：  
   - 开头使用 `ios::sync_with_stdio(false);` 和 `cin.tie(nullptr);` 提升 `cin`/`cout` 速度，注释已说明作用。  
   - 输出用 `'\n'` 而不是 `endl`，避免不必要的缓冲区刷新。

本题主解法已覆盖全部情况，无额外实现。

## 易错点

- **右值索引定位错误**：  
  容易把 `:=` 当成一个整体忽略，导致右值位置偏移。正确做法是 `i += 3` 指向右值。  
  *正确做法*：用 `i = i + 3` 跳过左变量、冒号、等于号。

- **变量作为右值时，是否取当前值**：  
  例如 `a:=b;`，应该将 `b` 的当前值赋给 `a`，而不是让 `a` 和 `b` 保持引用关系。  
  *正确做法*：直接读取 `var[right]` 的值赋给 `var[left]`，即值传递。

- **分号处理遗漏**：  
  如果忘记跳过分号，会导致下一个循环从分号开始解析，从而解析错误。  
  *正确做法*：每条语句处理后，`i += 2` 跳过右值和分号。

- **数组下标越界**：  
  使用 `var[128]` 并用字符 `'a'`、`'b'`、`'c'` 作下标，这些字符的 ASCII 均小于 128，安全。但若误用其他字符可能越界，不过输入保证合法。  
  *正确做法*：固定数组大小，并只使用合法字符下标。

- **数字字符转整数错误**：  
  直接写 `right` 会得到 ASCII 码，而不是数值。  
  *正确做法*：`right - '0'` 得到真正的整数。

## 总结发散

### 核心模式

“固定格式字符串 + 顺序解析 + 变量映射表”的模拟套路。

### 延伸/推导

如果变量数量增加到 26 个（`'a'` ~ `'z'`），仍然可以使用大小为 128 的数组，完全通用。  
如果赋值语句中出现更多运算符（如 `+`、`-`）或表达式，则需要更复杂的表达式解析（例如中缀转后缀、递归下降），但本题是最简单的赋值模拟。  
在实际编译器设计中，这种“词法分析 + 语法分析”的思路是基础，本题可以看作一个微型的解释器雏形。
