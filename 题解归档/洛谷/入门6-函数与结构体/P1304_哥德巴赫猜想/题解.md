## 题目描述

### 问题描述

输入一个偶数 \(N\)，验证 \(4\sim N\) 所有偶数是否符合哥德巴赫猜想：任一大于 \(2\) 的偶数都可写成两个质数之和。如果一个数不止一种分法，则输出第一个加数相比其他分法最小的方案。例如 \(10\)，\(10=3+7=5+5\)，则 \(10=5+5\) 是错误答案。

### 输入格式

第一行输入一个正偶数 \(N\)。

### 输出格式

输出 \(\dfrac{N-2}{2}\) 行。对于第 \(i\) 行：

首先先输出正偶数 \(2i+2\)，然后输出等号，再输出加和为 \(2i+2\) 且第一个加数最小的两个质数，以加号隔开。

### 数据范围

- \(4 \leq N \leq 10000\)
- 保证 \(N\) 为正偶数。

### 样例

#### 输入 #1

```
10
```

#### 输出 #1

```
4=2+2
6=3+3
8=3+5
10=3+7
```

## 解题思路

### 审题过程

- 题目要求验证从 4 到 N 的所有偶数（步长为 2）都能表示成两个质数之和。
- 对于每个偶数 \(x\)，我们需要找到一对质数 \(a\) 和 \(b\)，使得 \(a + b = x\)，并且 \(a \le b\)（事实上第一个加数最小自然保证 \(a \le b\)），同时要求 \(a\) 尽可能小。
- 输出格式固定：`偶数=质数+质数`，每行一个。

### 主解法选择说明

本题数据范围不大（\(N \le 10000\)），但我们要验证很多偶数（最多约 5000 个）。如果每判断一个偶数就重新检测两个数是否为质数，虽然也能过，但使用**埃拉托斯特尼筛法（埃氏筛）** 一次性预处理出所有质数，是教科书级的经典解法。这样后续每个偶数的验证都变成 \(O(1)\) 的查表操作，代码清晰且效率极高，非常适合初学者理解“空间换时间”的思想。因此我们选择埃氏筛作为主解法进行深度讲解。

### 主解法核心思路

埃氏筛法的核心思想是：从 2 开始，将每个质数的倍数都标记为合数（非质数）。  
例如：先假设所有数都是质数，然后依次看 2、3、5……如果当前数未被标记为合数，它就是质数，接着把它所有的倍数（从它的平方开始，因为更小的倍数已经被更小的质数标记过）都标记为合数。  
最终得到一个布尔数组 `isPrime[i]`，`true` 表示 \(i\) 是质数。  
之后对于每个偶数 \(x\)，我们从 2 开始枚举可能的第一个加数 \(p\)，只要 \(p\) 和 \(x-p\) 都是质数，就找到了最小方案，输出并跳出。

### 其他解法思路

本题解法较为固定，但也可以使用“直接判断质数法”作为另一种实现方式：

- **直接判断法**：不预先筛表，对每个偶数 \(x\)，枚举 \(p\) 从 2 到 \(x/2\)，每次都调用一个判断质数的函数（用试除法，检查能否被 2 到 \(\sqrt{n}\) 之间的整数整除）。由于 \(N\) 最多 10000，试除法的总复杂度约为 \(O(N \sqrt{N})\)，在本题数据下也可通过，但代码效率低于筛法，且重复计算较多。

### 主解法伪代码设计

```
输入 N
创建布尔数组 isPrime，大小 N+1，全部初始化为 true
isPrime[0] = isPrime[1] = false

// 埃氏筛
for i = 2 到 N:
    if isPrime[i] 为 true:
        for j = i * i 到 N，步长 i:
            isPrime[j] = false

// 输出每个偶数
for x = 4 到 N，步长 2:
    for p = 2 到 x / 2:
        if isPrime[p] 且 isPrime[x - p]:
            输出 x = p + (x-p)
            跳出内层循环
```

## 代码实现

### 主解法逐步讲解（带注释版本）

```cpp
#include <iostream>   // 提供 cin, cout 等输入输出流
#include <vector>     // 提供 vector 容器，用于动态数组

using namespace std;  // 允许直接使用 std 命名空间中的标识符，方便书写

int main() {
    // 用 ios::sync_with_stdio(false) 和 cin.tie(nullptr) 加速输入输出
    // 这是 C++ 竞赛中的常用优化，关闭 C 风格 IO 同步，减少 cin/cout 的开销
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;   // 读入上界 N

    // 创建布尔标记数组 isPrime，大小 N+1，并用 vector<char> 而非 vector<bool>
    // 原因：vector<bool> 是特化版本，其元素不是真正的 bool 类型，可能会带来意想不到的行为
    // 使用 vector<char> 行为与普通数组一致，内存占用也只多一点点，完全可接受
    vector<char> isPrime(N + 1, true);

    // 0 和 1 不是质数
    isPrime[0] = isPrime[1] = false;

    // 埃氏筛法：从 2 到 N 进行筛选
    for (int i = 2; i <= N; ++i) {
        if (isPrime[i]) {   // 如果 i 是质数
            // 将 i 的倍数标记为合数，从 i*i 开始（更小的倍数已被更小的质数标记过）
            // 注意：当 i 较大时，i*i 可能超过 int 范围，但这里 N ≤ 10000，安全
            for (int j = i * i; j <= N; j += i) {
                isPrime[j] = false;
            }
        }
    }

    // 验证 4 到 N 的所有偶数
    for (int x = 4; x <= N; x += 2) {
        // 从最小的质数 2 开始枚举第一个加数 p
        // 由于要求第一个加数最小，一旦找到就立即输出并跳出内层循环
        for (int p = 2; p <= x / 2; ++p) {
            if (isPrime[p] && isPrime[x - p]) {
                // 输出格式：x=p+(x-p)，使用 '\n' 换行，不用 endl
                // endl 会强制刷新缓冲区，降低性能，这里无交互式需求
                cout << x << '=' << p << '+' << (x - p) << '\n';
                break;  // 找到最小方案，跳出内层循环，继续下一个偶数
            }
        }
    }

    return 0;   // 程序正常结束
}
```

#### 第 1 步：头文件与命名空间

- `#include <iostream>`：包含了输入输出流对象 `cin`、`cout` 的定义。我们可以用它们从键盘读入数据，向屏幕输出结果。
- `#include <vector>`：提供了 `vector` 容器，它是一个动态数组，能根据需要自动调整大小。这里我们用 `vector<char>` 来存储质数标记，比静态数组更安全（不会意外越界），且内存分配在堆上，适合动态大小的需求。
- `using namespace std;`：C++ 标准库中的一切都放在 `std` 命名空间中，加上这一行后我们可以直接写 `cin`、`cout`、`vector` 等，而不用写成 `std::cin`、`std::vector`。对于初学者来说很方便，但在大型项目中可能引起命名冲突，不过竞赛题中通常可以安全使用。

#### 第 2 步：输入输出加速

- 我们在 `main` 函数开头写了两行：

  ```cpp
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  ```

  第一行用来取消 C++ 的 `cin`/`cout` 与 C 的 `scanf`/`printf` 之间的同步，第二行解除了 `cin` 与 `cout` 的绑定，这能显著提升大量输入输出时的速度。本题输出行数较多，使用后性能更好。

#### 第 3 步：创建标记数组

- `vector<char> isPrime(N + 1, true);` 创建了一个长度为 `N+1` 的 `char` 数组，并全部初始化为 `true`（即 `1`）。我们使用 `char` 而非 `bool` 是因为 `vector<bool>` 是一个特化版本，它的 `operator[]` 返回的是一个代理对象，而不是真正的 `bool&`，这会导致无法取地址等奇怪问题，初学者容易踩坑。`vector<char>` 的行为和普通数组完全一致，每个元素占 1 字节，内存开销很小（10001 个元素仅约 10KB），完全没问题。

#### 第 4 步：埃氏筛法

- 筛法从 `i = 2` 开始循环到 `N`。
- 如果 `isPrime[i]` 为真，说明 `i` 是质数，那么它的倍数（从 `i*i` 开始）都不是质数，将它们标记为 `false`。注意为什么从 `i*i` 开始？因为比 `i*i` 小的倍数，例如 `i*2`、`i*3`、……、`i*(i-1)`，一定已经被比 `i` 小的质数标记过了，这样可以减少重复标记，提高效率。
- 这里 `i*i` 不会溢出，因为 `N ≤ 10000`，`i ≤ 10000`，乘积最大为 1e8，在 `int` 范围内（约 21 亿）。

#### 第 5 步：枚举偶数并输出

- 外层循环 `for (int x = 4; x <= N; x += 2)` 遍历所有需要验证的偶数。
- 内层循环枚举第一个加数 `p`，从 2 开始到 `x/2` 为止（因为加法交换律，超过一半会重复）。
- 如果 `p` 和 `x-p` 都是质数（通过查表 `isPrime`），就找到了当前偶数的最小方案，输出并 `break` 跳出内层循环。使用 `'\n'` 而不是 `endl` 来换行，因为 `endl` 会强制刷新输出缓冲区，频繁刷新会拖慢速度，而这里没有交互式需求，用 `'\n'` 效率更高。

### 其他解法实现

本题主解法已覆盖全部情况，不过为了加深理解，我们提供一种“直接判断质数”的备选实现，适合在数据更小或不想预处理的场景使用。

#### 思路说明

- 不再事先筛出所有质数，而是对每个偶数 `x` 枚举可能的第一个加数 `p`。
- 写一个函数 `isPrimeNum(int n)`，用试除法判断 `n` 是否为质数：若 `n < 2` 返回 `false`；否则检查 `2` 到 `sqrt(n)` 之间的整数，若存在能整除 `n` 的数，则 `n` 为合数，否则为质数。
- 因为每次判断都要做试除，当 `N=10000` 时，总共约 5000 个偶数，每个偶数平均枚举约 1000 个 `p`，每个 `p` 判断复杂度约 `O(sqrt(N))` 即 100，总操作数约 5e8，在本题时限下可能较紧张，但合理优化后仍可通过（实际洛谷数据较为宽松）。不过该解法教学意义在于展示“质数判断函数”的写法，适合作为对照。

#### 完整代码

```cpp
#include <iostream>   // cin, cout
#include <cmath>      // sqrt 函数

using namespace std;

// 判断 n 是否为质数的函数
bool isPrimeNum(int n) {
    if (n < 2) return false;
    // 只需要检查到 sqrt(n) 即可
    int limit = (int)sqrt(n);  // cmath 中的 sqrt 返回 double，强转 int
    for (int i = 2; i <= limit; ++i) {
        if (n % i == 0) return false;
    }
    return true;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;

    for (int x = 4; x <= N; x += 2) {
        for (int p = 2; p <= x / 2; ++p) {
            if (isPrimeNum(p) && isPrimeNum(x - p)) {
                cout << x << '=' << p << '+' << (x - p) << '\n';
                break;
            }
        }
    }

    return 0;
}
```

#### 复杂度分析

- 时间复杂度：最坏情况下，外层循环约 \(N/2\) 次，内层平均约 \(N/4\) 次，每次判断质数约 \(O(\sqrt{N})\)，总复杂度约为 \(O(N^2 \sqrt{N})\)，对于 \(N=10000\) 约 \(10^4 \times 10^4 \times 10^2 = 10^{10}\) 级别，但实际上内层循环不会每次都枚举到 \(x/2\)，因为质数对通常较早出现，且判断质数在遇到小因子时提前返回，实际运行可接受，但理论效率远低于筛法。
- 空间复杂度：\(O(1)\)（仅用几个变量）。

### 解法对比总结

| 解法 | 时间复杂度 | 空间复杂度 | 代码复杂度 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| 埃氏筛法（主解法） | \(O(N \log \log N)\) | \(O(N)\) | 中等（需理解筛法逻辑） | 数据范围较大，需要频繁查询质数 |
| 直接判断质数法 | \(O(N^2 \sqrt{N})\)（实际近似 \(O(N^{2.5})\)） | \(O(1)\) | 低（只需写一个判断函数） | 数据范围很小（如 \(N \le 1000\)）或临时快速编写 |

**推荐建议**：

- **初学者建议掌握主解法（埃氏筛法）**，因为它体现了算法竞赛中非常重要的“预处理”思想，且能应对多数质数相关题目，代码复用性强。
- 进阶学习者可以了解直接判断法，它能帮助你理解质数判断的基本原理，但在大规模数据下不推荐使用。
- **竞赛中建议使用埃氏筛法**，因为 \(N=10000\) 时筛法几乎瞬间完成，且输出格式简单，无需过多优化。如果遇到更大数据（如 \(N=10^6\)），还可以进一步升级为欧拉筛（线性筛），但本题完全没必要。

## 易错点

- **数组越界**：如果使用静态数组 `bool isPrime[10005]`，要注意访问 `isPrime[N]` 时下标不超过数组大小。若使用 `vector`，通过 `vector<char> isPrime(N+1)` 动态分配，下标最大为 `N`，安全可靠。
- **未初始化变量**：`vector<char> isPrime(N+1, true)` 已经将所有元素初始化为 `true`，不会出现未初始化的问题。若使用静态数组，需要显式初始化。
- **整数除法陷阱**：在判断质数的试除法中，循环条件 `i <= sqrt(n)`，`sqrt` 返回 `double`，若直接比较整数 `i` 与 `double` 没有问题，但更好的做法是 `i * i <= n` 避免浮点误差，不过这里 `n` 很小，用 `sqrt` 也可以。
- **输出格式问题**：样例中输出没有多余空格或空行，我们使用 `cout << x << '=' << p << '+' << (x-p) << '\n';`，注意等号和加号都是字符，中间不能有多余空格。
- **`vector<bool>` 陷阱**：如果你使用 `vector<bool>`，可能会遇到取地址编译错误或代理对象带来的问题，所以强制使用 `vector<char>`。在本题中，使用 `vector<char>` 是安全且清晰的做法。
- **`endl` 性能问题**：输出换行时若使用 `cout << ... << endl;`，每执行一次都会刷新缓冲区，对于大量输出会显著降低速度。务必使用 `'\n'` 替代。
- **忘记加 `break`**：内层循环找到第一个可行方案后必须 `break`，否则会继续枚举更大的 `p`，导致输出错误（输出不是最小加数方案）。同时外层循环继续，不会影响，但内层必须跳出。

## 总结发散

### 核心模式

“预处理 + 枚举”：先用筛法一次性生成所有质数表，再对每个偶数从小到大枚举第一个加数，查表验证。

### 延伸/推导

埃氏筛法虽然简单，但存在重复标记的问题（如 6 会被 2 和 3 各标记一次）。**欧拉筛（线性筛）** 通过每个合数只被其最小质因子标记一次，将时间复杂度优化到 \(O(N)\)，在 \(N\) 达到 \(10^7\) 以上时效果显著。本题 \(N=10000\)，埃氏筛已经足够，但了解线性筛的原理有助于后续处理更大规模的数据。此外，哥德巴赫猜想本身是数论中的经典问题，目前尚未被完全证明，但在可验证范围内都成立，本题仅要求编程验证给定范围内的偶数，是入门级数论题。
