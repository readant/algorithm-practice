### B · qcjj的演唱会 —— AC 100/100 ✅

三场各排序，对第一场每首歌 `binary_search` 二、三场。结果 AC，复杂度 $O(n\log n)$ 正确。⚠️ **但 55 分钟段里大部分是翻笔记回忆"怎么对字符串数组排序+二分"，不是流畅写出**——B 的慢不是字符串难，是回忆缺失。详见 [B_我的提交.cpp](B_qcjj的演唱会/我的提交.cpp)。

### C · 小红的区间 —— 125/150 ⚠️【本场最该警醒的一题】

**你的代码**（[C_我的提交(错解).cpp](C_小红的区间/我的提交(错解).cpp)）：

```cpp
if (gcd(9, x) == 1) cout << "2 4\n";
else if (gcd(9, x) == 1) cout << "1 4\n";   // 全是 gcd(9,x)==1
else if (gcd(9, x) == 1) cout << "1 5\n";
else cout << "-1\n";
```

四个分支**完全一样**——复制粘贴后没改判断条件，等于根本没构造区间。能拿 125 纯属部分样例恰好命中。

**正解**（区间和构造，详见 [README](C_小红的区间/README.md)）：取最小长度 $k\ge 3$ 使 $\gcd(k,x)=1$，区间和 $=\frac{k(2l+k-1)}{2}$，再选 $l$ 让 $\frac{2l+k-1}{2}$ 与 $x$ 互质即可，必有解。

> 这是「**样例过就当对了**」的又一次复发——而且比前几场更离谱（前几场至少写了逻辑，这回连逻辑都省了）。

### D · 小红的排列构造 —— 26.67/200 ⚠️

**你的代码**（[D_我的提交(错解).cpp](D_小红的排列构造/我的提交(错解).cpp)）外层 `for` 未正常闭合、内层又用同名 `i` 重开循环，是「边读边乱填」的半成品，没有按「三组和的奇偶性相同」去构造。封榜最终 26.67（截图那次提交页显示 20.67，是中间提交，最终代码未抓取）。

**正解思路**：总和 $S=n(n+1)/2$，目标奇偶 $t=S\bmod 2$。每组和的奇偶 = 该组奇数个数 mod 2。$1..n$ 共 $O=\lceil n/2\rceil$ 个奇数，把 $O$ 个奇数分到 a/b/c 三组使每组奇数个数都 $\equiv t$，且不超过各组长度；分配得出就填奇数/偶数，否则 $-1$。详见 [README](D_小红的排列构造/README.md)。

## 五、不足分析

> ★ **本场最底层问题（赛后补充，推翻"字符串生锈"的浅层判断）**：前面几道（至少 A、B）赛时第一时间**全部想不起来做法，靠翻笔记才做出**。根因是**赛时回忆缺失**——"认得出笔记里的套路"不等于"写得出来"。字符串题只是排在最前、先暴露；C/D 的离谱失误也更可能是"翻到差不多的就急着装上去"的回忆缺失后遗症，而非纯知识盲区。下面 1–6 是它的表现或结果。

| 序号 | 不足 | 本场证据 | 性质 |
| :--: | :-- | :-- | :-- |
| 1 | **代码复制粘贴不检查** | C 题四分支全 `gcd(9,x)==1`，等于没做题 | **本场最致命，全新** |
| 2 | **样例过即认定正确** | C 靠样例蒙 125；与第 1 条同源 | 连续复发（第 N 次） |

## 六、训练方案

> 遵循 `COMPETE.md`：每周至多 1 场，赛后只补 1–3 题。

> ★ **本场新增的总方法（优先级高于 P0–P2）**：补题与日常练**第一遍必须盲做——不开笔记、不翻代码、凭记忆写**。卡住超 15 分钟才看笔记，看完**立刻盲重做一遍**。理由：本场暴露的是"认得出 ≠ 写得出"，多看笔记只会强化虚假熟练；只有 retrieval practice 能把 recognition 变成 recall。
