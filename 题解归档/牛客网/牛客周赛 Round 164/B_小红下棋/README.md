## 1. 题目描述

3×3 棋盘，小红（字符 `1`）与对手轮流下棋。给定当前局面，判断是否存在一个空格位置，让小红落子后**三连成一条线**。

- 有解：输出 `Yes`，下一行输出一组可行坐标 `i j`（1-based）
- 无解：输出 `No`
- **多解时输出任意一组即可**（Special Judge）

---

## 2. 解题思路

### 核心观察

棋盘只有 3×3 = 9 个格子，而"三连"的形态只有 8 种：

```
3 行 + 3 列 + 2 条对角线 = 8 条线
```

所以只需两层枚举：

1. **外层**：枚举所有空格（最多 9 个）
2. **内层**：检查落子后是否存在 8 条线之一全为 `1`

### 算法流程

```
枚举每个格子 (i, j)
  若该格为空 '*'：
    落子   c[i][j] = '1'
    若存在某条线三格皆为 '1'：
      输出 "Yes" 与 (i+1, j+1)，结束程序
    撤销   c[i][j] = '*'        ← 回溯
所有位置试完仍无解 → 输出 "No"
```

**为什么必须回溯：** 每个空格的尝试必须相互独立，否则第 2 个空格的判断会被第 1 次落子污染。这是"尝试—撤销—重试"模式（回溯）的最小实例。

## 3. 代码实现

```cpp
#include <iostream>
using namespace std;

char c[3][3];

// 判断小红是否三连
bool is_win() {
    // 3 行
    for (int i = 0; i < 3; i++)
        if (c[i][0] == '1' && c[i][1] == '1' && c[i][2] == '1')
            return true;
    // 3 列
    for (int j = 0; j < 3; j++)
        if (c[0][j] == '1' && c[1][j] == '1' && c[2][j] == '1')
            return true;
    // 2 条对角线
    if (c[0][0] == '1' && c[1][1] == '1' && c[2][2] == '1')
        return true;
    if (c[0][2] == '1' && c[1][1] == '1' && c[2][0] == '1')
        return true;
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    for (int i = 0; i < 3; i++)
        for (int j = 0; j < 3; j++)
            cin >> c[i][j];

    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 3; j++) {
            if (c[i][j] == '*') {
                c[i][j] = '1';                 // 模拟落子
                if (is_win()) {
                    cout << "Yes\n";
                    cout << i + 1 << " " << j + 1 << "\n";
                    return 0;
                }
                c[i][j] = '*';                 // 回溯，恢复空位
            }
        }
    }

    cout << "No\n";
    return 0;
}
```

### 关键行注释

| 行 | 作用 |
| :-- | :-- |
| `c[i][j] = '1';` | 模拟小红落子 |
| `cout << i + 1 << " " << j + 1;` | 下标 0-based → 输出 1-based |
| `c[i][j] = '*';` | **回溯**，恢复现场继续枚举 |

## 5. 易错点

1. **忘记回溯** —— `c[i][j] = '*'` 漏掉，后续判断全部基于脏状态。
2. **坐标基准搞错** —— 数组 0-based，输出要求 1-based，需 `+1`。
3. **只输出 `Yes` 不输出坐标** —— 题目要求两行输出。
4. **多解时纠结唯一答案** —— 本题多解输出任意一组，看到别人的答案和自己不同不代表错。

## 6. 赛后改进项（待办）

虽已 AC，但有三处值得改：

1. **`'1'` 硬编码** —— `c[i][j] == '1'` 依赖字符约定。本轮数据恰好是 `1`/`2`/`*`，所以能过。稳妥写法：把空格 `'*'` 替换为固定常量再比较，避免依赖 `'1'` 的具体含义。
2. **`is_win()` 语义不完整** —— 只检查 `1` 三连。若判题数据出现"对手已三连"的局面，会误判为可赢。严格应先判断游戏是否已结束。
3. **44 分钟偏长** —— 核心逻辑 10 分钟可写完。超时部分主要是首次参赛的流程损耗（熟悉提交界面、等待评测、切题节奏）。**下场比赛这部分成本归零。**
