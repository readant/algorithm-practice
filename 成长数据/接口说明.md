# 算法成长数据 · 接口说明

> **面向 AI / 程序的读取接口。** 本目录是「算法方向成长」的唯一数据出口；  
> 本仓的仪表盘与外部系统（如 Ambition）都从这里取数，各自消费，互不绑定。

---

## 0. 一句话

```
真实比赛/比赛记录/*.json  ┐
                          ├─(growth_core 计算)─▶  成长数据/snapshot.json  (全量机器可读)
训练记录/日志/*.json      ┘                       成长数据/brief.md      (给 AI 的精简摘要)
                                                  可视化/dashboard.html  (给人看的图)
   两个真值源（人写）
```

**单向、幂等**：所有下游文件都由真值源派生；生成器**只读真值源、只写派生文件，绝不回写**。

**两个真值源的分工**：

| 真值源          | 覆盖        | 关键防伪字段                  |
| :----------- | :-------- | :---------------------- |
| `真实比赛/比赛记录/` | 赛场（低频高信号） | 名次 / 每题得分与用时 / 封榜通过率    |
| `训练记录/日志/`   | 日常训练（高频）  | **`independent` 独立完成度** |

> 训练层的核心是**独立完成度**：AC 数可以刷（抄一遍也算 AC），只有"独立 / 卡住后自己过 / 看题解后过"能区分真实成长与伪装。



---

## 1. 命令（给 AI 用，人不用记）

**只有一个脚本、一条命令。**

| 命令 | 作用 |
| :-- | :-- |
| `python 可视化/build.py` | **默认**：校验 + 导出 `snapshot.json` + `brief.md` + 生成 `dashboard.html` |
| `python 可视化/build.py --brief` | 只打印**精简摘要**到 stdout（约 1.8 KB）——**AI 首选**，最省 token |
| `python 可视化/build.py --check` | 只校验两个真值源（有错退出码 1） |
| `python 可视化/build.py --open` | 跑完顺便打开仪表盘 |

不需要 Python 也能消费：`成长数据/snapshot.json` 与 `brief.md` 是**已提交的静态文件**，直接读即可。

### 人的入口不是命令，是 `随手记.md`

**人只写根目录的 [`../随手记.md`](../随手记.md)**（自由格式，一行一题，写清 日期/平台/题号/结果/**是否独立**）。
AI 负责把它转成 `真实比赛/比赛记录/` 与 `训练记录/日志/` 下的结构化 JSON，再跑上面的命令。
**不要让本人去手写 JSON 或记命令——这是设计约定，不是建议。**

## 2. `snapshot.json` 字段

顶层：

| 字段                  | 说明                                                                          |
| :------------------ | :-------------------------------------------------------------------------- |
| `schema_version`    | 当前 `"1.0"`。**只增不改**；破坏性变更才升版本                                               |
| `generated_at`      | 生成时间。判断数据新旧看它                                                               |
| `source`            | 真值源路径，恒为 `真实比赛/比赛记录/*.json`                                                 |
| `contests_count`    | 已录入场数                                                                       |
| `latest_contest_id` | 最近一场的 id                                                                    |
| `config`            | 当前生效的阈值（止损线、档位边界、趋势线门槛）——**别把它写死在分析里**                                      |
| `latest`            | 最近一场的完整块（见下）                                                                |
| `history[]`         | 逐场同结构块，按日期升序                                                                |
| `stagnation[]`      | **停滞项**：`label / key / value / streak / verdict / severity`。`streak ≥ 2` 才算 |
| `progress[]`        | 最近两场对比的进步/退步项：`label / unit / detail{from,to,delta,good}`                   |
| `constraints[]`     | 当前场数 / 训练日数下**禁止**做哪些分析（趋势线 / 回归 / 雷达）                                      |
| `training`          | 训练层聚合（见下）；`status:"empty"` 表示训练记录尚未录入                                       |
| `warnings[]`        | 数据质量问题（如时间线为重建值、缺总人数）                                                       |

单场块（`latest` 与 `history[]` 元素）：

| 字段                                                                                                             | 说明                                                                                                                                                   |       |
| :------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `id / platform / name / date / contest_system`                                                                 | 赛事元信息                                                                                                                                                |       |
| `total_possible / my_total / rank / participants / percentile / score_rate`                                    | 成绩。`participants` 或 `rank` 缺失时 `percentile` 为 `null`                                                                                                 |       |
| `solved_full_count / partial_count / problem_count`                                                            | 完全通过 / 部分分 / 总题数                                                                                                                                     |       |
| `midtier{closed,total}`                                                                                        | 中档题闭环数（核心短板指标）                                                                                                                                       |       |
| `by_tier{签到,简单,中档,困难}{total,full,attempted}`                                                                   | 分档产出                                                                                                                                                 |       |
| `efficiency{signin_minutes,total_minutes_used,idle_tail_minutes,score_per_minute}`                             | 效率                                                                                                                                                   |       |
| `discipline{stop_loss_executed,stop_loss_violations,ordering_followed,expected_ordering,attempted_nontrivial}` | 纪律                                                                                                                                                   |       |
| `gaps{expected_loss_reachable,missing_highest_expected{letter,expected_score}}`                                | 失分归因                                                                                                                                                 |       |
| `tier_border_problems[]`                                                                                       | 通过率距档位边界 ≤2pp 的题（判定存疑）                                                                                                                               |       |
| `problems[]`                                                                                                   | 逐题：`letter/title/full_score/tier/tier_border/primary_rate/expected_score/my_score/status/attempted/time_spent_minutes/post_contest_score/tags/notes` |       |
| `timeline[]`                                                                                                   | 阶段：\`stage/start/end/minutes/score_gained/kind(题                                                                                                     | 空转)\` |
| `timeline_reconstructed`                                                                                       | `true` 表示时间线为按累计时长重建（非原始起止时刻）                                                                                                                        |       |
| `provenance`                                                                                                   | `entered_by/entered_at/sources[]/confidence`                                                                                                         |       |

`training`（训练层聚合，字段与比赛层独立）：

| 字段                                                            | 说明                                                             |
| :------------------------------------------------------------ | :------------------------------------------------------------- |
| `status`                                                      | `"ok"` 或 `"empty"`（`empty` 时其余字段不存在）                           |
| `days / date_first / date_last`                               | 训练日数与首末日期                                                      |
| `training_streak_days`                                        | 从最近训练日往前数的**日历连续**天数                                           |
| `problems_total / ac_count / problems_per_day`                | 题量；`ac_count` 为 `verdict=="AC"` 的题数                            |
| `scored_count`                                                | **有完成度标注的题数**（`independent` 非 null）——所有比率的分母                   |
| `independent_count / hinted_count / solution_dependent_count` | 独立 / 卡住后自己过 / 看题解后过                                            |
| `independent_ac_rate`                                         | **核心诚实指标** = 独立题数 / `scored_count`；`scored_count==0` 时为 `null` |
| `dependency_rate`                                             | (卡住后 + 看题解后) / `scored_count`                                  |
| `weak_problem_count`                                          | 弱证据题数（**不参与**上面的比率）                                            |
| `evidence_records` / `evidence_problems`                      | 按证据等级（强/中/弱）的记录数 / 题数                                          |
| `by_tag`                                                      | 标签 → `{scored, independent, independent_rate}`，按 `scored` 降序   |
| `median_minutes_per_problem`                                  | 单题中位耗时（仅有 `minutes` 的题）                                        |
| `constraints[]`                                               | 训练日 < 4 时禁止画训练趋势线                                              |

## 3. 写接口

**分工：人写 `随手记.md`（自由格式）→ AI 转成结构化 JSON → 跑 `build.py`。**

### 比赛（`真实比赛/比赛记录/`）

```bash
# AI 做的事：从 随手记.md 解析出比赛 → 写 YYYY-MM-DD_赛事名.json（可复制 _模板.json）
# 字段语义见 真实比赛/schema.json；缺失一律写 null，不要省略键、不要猜
python 可视化/build.py            # 校验 + 导出 + 出图（有错会指出文件名与键路径）
python 可视化/build.py --open     # 需要看 HTML 时
```

**AI 整理比赛数据时的硬规则**：

1. `my_total` **不含** `post_contest_score`（赛后补题分单列，官方不计入排行）。
2. 难度档只用**封榜**通过率算；`official_final`（含赛后补题）会虚高，只作参考。
3. 通过率写 `numerator`/`denominator`，让脚本现算（手写的 `rate` 只是兜底，别依赖）。
4. `participants` 不知道就写 `null`，**不要编造百分位**。
5. `status` 四值语义：`full` 完全通过 / `partial` 部分分 / `failed` 提交未过 / `unattempted` 未提交。
6. 改了数字要同步更新 `provenance.entered_at` 与 `sources`。

### 训练记录（`训练记录/日志/`）

一天一个文件 `YYYY-MM-DD_平台.json`，`problems[]` 逐题记。**AI 从 `随手记.md` 解析生成**，然后：

```bash
python 可视化/build.py            # 校验 + 导出 + 出图
```

1. **`independent` 是整个训练层最重要的字段**，三值：`独立` / `卡住后自己过` / `看题解后过`。**记不清就写 `null`，绝不为了凑数乱填**。
2. **`evidence_level` 必须诚实**：`强`=平台判定 + `code_file` 指向原始代码；`中`=自述 + 截图；`弱`=仅有题号/题单记载。  
   （`check` 会对"标为强证据但无 `code_file`"报警告。）
3. **`attempts` / `minutes` 记不清写 `null`——估出来的数字比没有更糟。**
4. 原始代码放 `训练记录/原始代码/<日期>/`，`code_file` 填**相对 `训练记录/原始代码/`** 的路径。
5. 批量/回顾性录入用 `date_range` + `evidence_level:"弱"`，并把单题 `independent` 留 `null`。
6. 人在 `随手记.md` 里没写"是否独立"时：**不要替他猜**，留 `null` 并提示他下次补上。

## 4. AI 分析时的硬规则（诚实约束）

这些规则是**在生成器里已落地**的，AI 回答时不要绕过：

- **场数 < `config.trend_min_contests`（默认 4）禁止画跨场趋势线**；< 5 禁止回归/预测；< 3 禁止雷达面积对比。  
  用 `constraints[]` 字段判断当前能不能做，不要凭感觉。
- **优先说「没变的」**：`stagnation[]` 里 `streak ≥ 2` 的项排在进步项之前。只报得分率上升会变成安慰剂。
- **`tier_border_problems` 非空时必须提示档位判定存疑**（如 165 的 C 题 59.7%，距 60% 边界 0.3pp）。
- **`timeline_reconstructed: true` 时**不得把时间线当作精确事实。
- 指标口径见 `可视化/README.md`；档位划分：签到 ≥90% / 简单 60–90% / 中档 30–60% / 困难 <30%。

### 训练层的额外硬规则

- **`independent_ac_rate` 为 `null` 时，必须说"不可计算"**，不得用 `ac_count` 冒充独立完成量。
- **弱证据题（`evidence_level:"弱"` 或无 `independent` 标注）不得用于任何"能力"结论**，只能算"做过"。  
  引用训练数据时要说清它属于哪一档证据。
- `training.training_streak_days` 是按**日历**连续性算的；`date_range` 批量记录只会落在区间结束日，会让 streak 失真——引用时注意。
- 训练日 < `constraints[]` 里的门槛时，同样禁止画训练趋势线。

| 文件              | 性质                     |
| :-------------- | :--------------------- |
| `接口说明.md`       | **手写**：本文件，接口契约        |
